## 2. 总体结论

当前项目已经具备“智能体平台底座”的核心能力，包括智能体应用管理、知识库、文档分段、向量化、混合检索、RAG 对话、模型供应商管理、工具工作流、MCP、触发器、用户与资源授权、对话用户认证、钉钉扫码登录基础对接等。

但从建设文档来看，目标并不只是一个通用智能体平台，还包含营销推荐、AI 分析报告、模型全生命周期、监控告警、IVR、业务系统集成、数据主题库、仿真预演、上云部署、安全三同步和数据安全等内容。当前项目对这些能力多数属于“有平台基础，但没有行业业务闭环”。

因此建议不要一次性大改，而是按 PRD 分阶段扩展：

1. 先补齐智能体平台与建设文档直接相关的短板：知识库治理、检索评估、合规审核、权限审计、对话用户体系。
2. 再扩展运营侧能力：AI 分析报告、监控告警、模型评估、数据接入。
3. 最后做重业务能力：营销推荐、IVR、仿真预演、外部业务系统对接。

## 6. 建议后续 PRD 清单

### PRD-01 服务助手知识库增强与检索评估

优先级：P0

目标：把当前知识库从“能导入、能检索”升级为“可评估、可调优、可运营”的知识库能力。

主要范围：

- 文档解析策略配置：按文件类型配置解析器、分段方式、标题层级保留、表格处理方式。
- 分段策略增强：支持递归分段、标题感知分段、表格行列结构化分段、问答对分段。
- 检索评估集：维护问题、期望命中文档、期望段落、期望答案。
- 命中测试增强：展示向量分、关键词分、融合分、reranker 分。
- 知识库索引版本：支持索引构建、发布、回滚、对比。
- 质量指标：召回率、命中率、无答案率、人工纠错率。

建议原因：这是当前项目基础最好、离建设文档最近的部分，投入产出最高。

### PRD-02 RAG 答案质量与内容合规审核

优先级：P0

目标：补齐建设文档里的“增强生成与合规审核”要求，降低幻觉和违规输出风险。

主要范围：

- 答案生成前的敏感词、禁答规则、业务范围判断。
- 答案生成后的合规审核模型/规则。
- 引用来源强制展示与来源可信度评分。
- 无依据回答拦截。
- 人工反馈闭环：点赞、点踩、纠错进入知识库待优化池。
- 合规审核日志和统计报表。

建议原因：适合先做成平台能力，后续营销、政务、人社场景都能复用。

### PRD-03 对话用户认证、用户组与资源授权完善

优先级：P0

目标：完善钉钉/本地对话用户的权限模型，让“谁能访问哪个智能体、哪个知识库”清晰可控。

主要范围：

- 对话用户来源统一：LOCAL、DINGTALK 等来源标准化。
- 钉钉用户组默认授权策略配置化。
- 应用授权和知识库授权联动检查。
- 未授权访问错误页与引导。
- 管理端授权审计。
- 外部账号绑定、解绑、冲突处理策略。

建议原因：你最近已经在做钉钉扫码和知识库授权，这块应该尽快产品化。

### PRD-04 API 编排工具对接与晓搭平台适配

优先级：P1

目标：把当前工具/工作流能力对外包装成可注册、可调用、可授权的开放工具。

主要范围：

- 工具元数据模型：名称、描述、图标、输入参数、输出 schema。
- 工具注册接口：同步到晓搭或第三方平台。
- 调用协议适配：请求参数转换、认证、响应格式转换。
- 工具调用权限：按工作空间、用户组、应用授权。
- 调用日志和失败重试。
- 工具可视化入口配置。

建议原因：当前项目已有工具工作流基础，适合做“平台对平台”的集成扩展。

### PRD-05 智能体事件调度与任务编排中心

优先级：P1

目标：从单个应用/工具工作流，升级到跨智能体、跨工具、跨事件的统一任务调度。

主要范围：

- 事件网关：webhook、定时、业务事件、系统事件统一接入。
- DAG 任务编排：任务节点、依赖、条件分支、失败分支。
- 执行状态追踪：运行中、成功、失败、重试、跳过、取消。
- 资源调度：模型并发、工具并发、API 配额、优先级。
- 冲突管控：同资源互斥锁、任务去重、幂等键。
- 执行日志与链路追踪。

建议原因：当前已有 trigger 和 workflow，但缺“全局调度视角”。

### PRD-06 AI 分析报告中心（粗粒度 V1 已完成）

优先级：P1

目标：实现建设文档中的“数据自动采集 + 模板引擎 + LLM 报告生成 + 订阅分发”。

主要范围：

- 数据源配置：数据库、API、CSV/Excel、手工上传。
- 指标口径管理：曝光、点击、转化、复购、流失等指标定义。
- 报告模板管理：变量、图表、段落、LLM 生成块。
- 报告生成任务：手动生成、定时生成、失败重试。
- 报告输出：HTML、Word、PDF。
- 报告订阅：每日、每周、每月；邮件、站内消息、下载中心。

建议原因：可以复用当前 LLM、触发器、文件导出和系统设置能力。

### PRD-07 监控指标与告警中心

优先级：P1

目标：建设模型、知识库、应用、系统资源的统一监控告警体系。

主要范围：

- 指标中心：模型调用、响应时间、错误率、token、知识库命中率、用户活跃。
- 告警规则：阈值、同比环比、连续失败、数据延迟。
- 通知渠道：邮件、钉钉、webhook。
- 告警处理：认领、派单、关闭、备注、回溯。
- 看板：应用运行、模型运行、知识库质量、系统资源。

建议原因：这是上线运营必备能力，也能支撑建设文档的“效果监控”和“监控排障屏”。

### PRD-08 模型生命周期与评估管理

优先级：P2

目标：补齐 MLflow、训练评估流水线、模型注册、版本和发布回滚能力。

主要范围：

- 模型实验记录：参数、数据集、指标、产物。
- 模型注册表：版本、状态、适用场景、负责人。
- 评估任务：离线评估集、RAG 评估、推荐模型评估。
- 发布流程：灰度、回滚、审批。
- MLflow 对接。
- 训练任务流水线和任务审计。

建议原因：当前模型管理偏“供应商配置”，还不是“模型研发治理平台”。

### PRD-09 营销推荐引擎

优先级：P2

目标：建设双塔召回、多路召回、精排、增量学习、效果监控的营销推荐闭环。

主要范围：

- 用户画像：静态特征、行为序列、上下文特征。
- 物料库：营销内容、产品、活动、标签、上下线。
- 双塔召回：离线训练、物料向量预计算、在线用户向量计算。
- 多路召回：协同过滤、内容相似、热点趋势、地域偏好、规则召回。
- 精排：CTR/CVR/停留时长多目标排序。
- 反馈闭环：曝光、点击、转化、负反馈。
- 效果监控：CTR、CVR、GMV、覆盖率、多样性、延迟。

建议原因：这是独立业务系统级能力，和当前 RAG 平台差距最大，建议后置。

### PRD-10 IVR 语音服务助手接入

优先级：P2

目标：支持电话语音流接入智能体，实现语音转写、意图识别、状态同步和响应指令返回。

主要范围：

- IVR 接入协议。
- 实时语音流接收。
- 流式 STT。
- 会话状态机：菜单层级、已输入信息、上下文。
- MQ 状态同步：开始、结束、转接。
- 响应指令：播报文本、转人工、跳转菜单、结束通话。
- 通话日志和质检。

建议原因：当前已有 STT/TTS 基础，但 IVR 是独立通道，需要专项设计。

### PRD-11 场景模拟与故障预演平台

优先级：P2

目标：覆盖建设文档里大量“模拟申告、告警模拟、故障配置、场景回溯、能力调用模拟”等预演能力。

当前进展（2026-09-14）：M10-01 已完成统一预演底座与 X18 申告模拟，M10-02 已完成 X19 处置进度模拟，M10-03 已完成 X20 自定义数据构造与趋势看板；后续从 X21 场景模拟继续，不能因已有底座提前判定整个 PRD-11 完成。

主要范围：

- 预演场景库：场景配置、克隆、版本。
- 模拟数据模型：公客、政企、申告、告警、时序数据。
- API Mock 框架。
- 故障模板库和故障等级。
- 动态剧本编辑器。
- 流程回放、拓扑快照、操作镜像对比。
- 模拟结果报告下载。

建议原因：体量大，业务强，适合在调度中心和监控中心之后建设。

### PRD-12 外部业务系统 AI 接入适配

优先级：P2

目标：让当前智能体平台能够接入营销、客服、工单、告警、派单等外部业务系统，而不是把所有业务系统重做在平台内部。

主要范围：

- 外部业务 API 适配器。
- 用户、产品、活动、工单、告警、派单等业务数据映射。
- 业务知识库同步。
- 营销服务助手。
- 客服辅助智能体。
- 运维处置助手。
- 管理端智能问数和看板问答。
- 数据权限、脱敏和审计。

建议原因：建设方案涉及多类业务系统和外部平台，建议先做 AI 接入层，避免把当前项目改成完整业务系统。

### PRD-13 政务安全、双因素认证与审计增强

优先级：P1

目标：补齐建设方案中的安全、认证、访问控制、安全三同步和审计要求。

主要范围：

- 账号密码 + 短信验证码双因素认证。
- 登录设备、IP、失败次数、锁定策略。
- 敏感数据脱敏。
- 操作审计日志增强。
- 文件访问有效期和外发记录。
- 密钥管理和云安全服务适配预留。
- 安全配置检查。

建议原因：如果要上线政企/政务环境，这块优先级应提前。

## 7. 建议开发顺序

### 第一阶段：平台可上线基础增强

建议先做：

1. PRD-03 对话用户认证、用户组与资源授权完善
2. PRD-01 服务助手知识库增强与检索评估
3. PRD-02 RAG 答案质量与内容合规审核
4. PRD-13 政务安全、双因素认证与审计增强

阶段目标：让当前平台在权限、知识库、回答质量、安全方面具备可交付基础。

### 第二阶段：运营和集成能力

建议继续做：

1. PRD-04 API 编排工具对接与晓搭平台适配
2. PRD-05 智能体事件调度与任务编排中心
3. PRD-07 监控指标与告警中心
4. PRD-06 AI 分析报告中心（粗粒度 V1 已完成，冻结非阻塞优化）

阶段目标：把平台从“能对话”升级到“能编排、能监控、能报告、能对接外部系统”。

### 第三阶段：行业业务能力

建议最后做：

1. PRD-12 外部业务系统 AI 接入适配
2. PRD-10 IVR 语音服务助手接入
3. PRD-11 场景模拟与故障预演平台
4. PRD-09 营销推荐引擎
5. PRD-08 模型生命周期与评估管理

阶段目标：进入具体行业场景和模型研发治理，形成业务闭环。

## 8. 下一步建议

建议下一步先从 P0 里选一个 PRD 正式展开。优先推荐 `PRD-03 对话用户认证、用户组与资源授权完善`，原因是它和最近已经做过的钉钉扫码、对话用户、知识库授权最接近，改动范围可控，也能马上解决实际访问问题。

第二推荐 `PRD-01 服务助手知识库增强与检索评估`，它直接对应建设文档里的知识库构建、向量化、混合检索、重排序，是当前项目最容易形成亮点的方向。
