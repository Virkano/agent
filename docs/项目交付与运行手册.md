# 线上营销智能体平台项目交付与运行手册

## 1. 文档说明

本文用于源码仓库、业务镜像或离线镜像包交付后的首次安装、启动、验收、日常启停和常见故障处理。

所有命令默认从仓库根目录执行。命令中的 `<...>` 为需要替换的部署参数，不应原样执行。

## 2. 交付边界

### 2.1 交付内容

| 交付物 | 路径或名称 | 说明 |
| --- | --- | --- |
| 业务源码 | 当前仓库 | 前后端、任务服务、本地向量服务源码 |
| 业务镜像定义 | `docker/Dockerfile.app` | 构建唯一业务镜像 |
| 容器编排 | `docker-compose.yml` | 只编排业务容器 |
| 环境变量模板 | `docker/.env.example` | 外部依赖和运行参数模板 |
| 数据库初始化脚本 | `docker/initdb.sql` | 幂等创建空数据库并启用 pgvector |
| 容器启动脚本 | `docker/start-app.sh` | 安全检查、依赖等待和服务启动 |

### 2.2 不包含的基础设施

以下组件由部署环境独立提供，不打入业务镜像：

- PostgreSQL；
- Redis；
- Ollama 大模型服务；
- HTTPS 证书和反向代理。

业务镜像内部已经包含管理端、聊天端、Django、Celery 和本地向量服务。本地向量服务只监听容器内 `127.0.0.1:11636`，无需额外暴露端口。

## 3. 部署前检查

### 3.1 主机要求

- 已安装 Docker Engine；
- 使用 `docker compose version` 能看到 Compose v2；
- 对外端口 `8080` 未被其他程序占用；
- 业务容器能够访问 PostgreSQL、Redis 和 Ollama；
- 构建主机能够访问项目依赖源，或已经准备离线业务镜像。

检查 Docker：

```bash
docker version
docker compose version
docker info
```

### 3.2 PostgreSQL

PostgreSQL 必须已经安装 pgvector。使用管理员账号检查：

```bash
psql -h <postgres-host> -p 5432 -U <admin-user> -d postgres \
  -c "SELECT version();"
```

初始化脚本不会创建数据库账号。业务账号必须提前存在，并对目标数据库具备连接、建表、序列和读写权限。如果初始化管理员与 `JB_DB_USER` 不是同一账号，应由数据库管理员完成授权。

### 3.3 Redis

无密码实例：

```bash
redis-cli -h <redis-host> -p 6379 PING
```

有密码实例建议使用交互式密码输入，避免把密码写入命令历史：

```bash
redis-cli -h <redis-host> -p 6379 --askpass PING
```

正常结果为 `PONG`。

### 3.4 Ollama

在 Ollama 所在主机或可访问网络中检查：

```bash
curl -fsS http://127.0.0.1:11434/api/tags
```

如果使用远程 HTTPS 服务：

```bash
curl -fsS https://ollama.example.com/api/tags
```

接口成功只代表 Ollama 服务在线，还应确认业务使用的模型已经出现在返回列表中。模型本体不进入业务镜像。

## 4. 首次部署

### 4.1 初始化数据库

从能够访问 PostgreSQL 的主机执行：

```bash
psql -h <postgres-host> -p 5432 -U <admin-user> -d postgres \
  -v app_db=initdb \
  -f docker/initdb.sql
```

脚本行为如下：

- 目标数据库不存在时创建 `initdb`；
- 目标数据库已存在时保留原库，不覆盖、不清理数据；
- 在目标数据库启用 `vector` 扩展；
- 不导入账号、验收数据、Token、API Key 或模型密钥。

如果 PostgreSQL 运行在单独的 Docker 容器中，也可以把脚本通过标准输入传入：

```bash
docker exec -i <postgres-container> \
  psql -U <admin-user> -d postgres -v app_db=initdb -f - \
  < docker/initdb.sql
```

验证结果：

```bash
psql -h <postgres-host> -p 5432 -U <admin-user> -d initdb \
  -c "SELECT current_database(), extversion FROM pg_extension WHERE extname = 'vector';"
```

业务表不由该 SQL 固化维护。业务容器启动后会自动执行当前代码版本的 Django migrations，确保数据库结构与代码一致。

### 4.2 创建运行配置

```bash
cp docker/.env.example docker/.env
```

编辑 `docker/.env`。本地或测试环境的最小配置示例：

```dotenv
JB_APP_IMAGE=telecom-ai-agent:local
JB_APP_PORT=8080
JB_DEPLOYMENT_MODE=local

JB_DB_NAME=initdb
JB_DB_HOST=host.docker.internal
JB_DB_PORT=5432
JB_DB_USER=root
JB_DB_PASSWORD=<数据库密码>

JB_REDIS_HOST=host.docker.internal
JB_REDIS_PORT=6379
JB_REDIS_DB=0
JB_REDIS_PASSWORD=<Redis密码，无密码时留空>

JB_OLLAMA_BASE_URL=http://host.docker.internal:11434
JB_DEFAULT_PASSWORD=<全新数据库的管理员初始密码>
```

地址配置规则：

- PostgreSQL、Redis、Ollama 在宿主机并已发布端口：使用 `host.docker.internal`；
- 服务位于其他服务器：填写可从业务容器访问的域名或 IP；
- Ollama 使用 HTTPS：填写类似 `https://ollama.example.com` 的基础地址，不追加 `/api`；
- `127.0.0.1` 在业务容器中表示业务容器自身，不能用来访问宿主机 Ollama。

`docker/.env` 已加入 `.gitignore` 和 `.dockerignore`，不得提交真实口令或密钥。

### 4.3 校验 Compose 配置

```bash
docker compose --env-file docker/.env config
```

该命令应成功输出解析后的 Compose 配置。输出可能包含环境变量值，不要把结果粘贴到公开日志或提交到仓库。

### 4.4 构建业务镜像

```bash
docker compose --env-file docker/.env build app
```

确认镜像：

```bash
docker image inspect telecom-ai-agent:local \
  --format '{{.RepoTags}} {{.Config.ExposedPorts}}'
```

镜像应只声明 `8080/tcp`。PostgreSQL、Redis 和 Ollama 镜像不属于本项目构建结果。

### 4.5 启动业务容器

```bash
docker compose --env-file docker/.env up -d --no-build app
```

容器启动过程会依次执行：

1. 部署安全门禁检查；
2. 等待 PostgreSQL 和 Redis 端口可连接；
3. 启动容器内本地向量服务；
4. 自动执行 Django migrations；
5. 启动 Web 和后台任务进程。

查看状态和日志：

```bash
docker compose --env-file docker/.env ps
docker compose --env-file docker/.env logs --tail=200 app
```

首次启动需要执行全部迁移，耗时通常长于普通重启。应等待健康状态正常后再登录。

## 5. 启动验收

### 5.1 健康检查

```bash
curl -fsS http://127.0.0.1:8080/healthz
```

正常响应：

```json
{"status":"ok"}
```

该接口检查 PostgreSQL 查询、Redis 读写和容器内向量服务。它不检查外部 Ollama，因此还需单独验证 `/api/tags` 和一次真实模型调用。

### 5.2 页面入口

| 页面 | 地址 |
| --- | --- |
| 管理端 | `http://<部署主机>:8080/admin/` |
| 聊天端 | `http://<部署主机>:8080/chat/` |
| 管理 API 文档 | `http://<部署主机>:8080/admin/api-doc/` |
| 健康检查 | `http://<部署主机>:8080/healthz` |

全新数据库首次登录：

- 用户名：`admin`；
- 密码：数据库第一次迁移时配置的 `JB_DEFAULT_PASSWORD`。

修改 `JB_DEFAULT_PASSWORD` 不会自动重置已经初始化数据库中的管理员密码。首次登录后应立即修改默认密码。

### 5.3 最小验收清单

- `docker compose ps` 显示业务容器正在运行且健康；
- `/healthz` 返回 HTTP 200 和 `{"status":"ok"}`；
- 管理端登录页可以打开；
- 管理员可以登录并进入默认工作空间；
- 管理 API 未登录访问返回 401，而不是 404 或 500；
- Ollama `/api/tags` 可从部署网络访问；
- 在系统模型管理中配置 Ollama 模型后，模型连通性测试通过；
- 创建知识库后可完成一次文档向量化和检索；
- 创建智能体后可完成一次带引用的对话；
- 日志中没有出现数据库口令、Redis 口令或模型凭证。

## 6. 日常运行管理

### 6.1 查看状态

```bash
docker compose --env-file docker/.env ps
docker compose --env-file docker/.env logs --tail=200 app
docker compose --env-file docker/.env logs -f app
```

### 6.2 重启

```bash
docker compose --env-file docker/.env restart app
```

环境变量或镜像发生变化时，重新创建容器：

```bash
docker compose --env-file docker/.env up -d --force-recreate --no-build app
```

### 6.3 停止

```bash
docker compose --env-file docker/.env stop app
```

停止并移除业务容器和 Compose 网络：

```bash
docker compose --env-file docker/.env down
```

镜像不能被“停止”，只能停止使用镜像运行的容器。普通 `down` 不删除业务数据卷，也不会操作外部 PostgreSQL 或 Redis。除非已经确认可以清除容器持久化目录，否则不要执行：

```text
docker compose down -v
```

### 6.4 更新版本

源码交付更新：

```bash
docker compose --env-file docker/.env build app
docker compose --env-file docker/.env up -d --force-recreate --no-deps app
curl -fsS http://127.0.0.1:8080/healthz
```

更新前应备份 PostgreSQL。新容器启动时会自动执行新增 migrations。

## 7. 离线镜像交付

构建方导出唯一业务镜像：

```bash
docker save -o telecom-ai-agent-local.tar telecom-ai-agent:local
```

可选校验：

```bash
shasum -a 256 telecom-ai-agent-local.tar
```

目标环境导入：

```bash
docker load -i telecom-ai-agent-local.tar
docker image inspect telecom-ai-agent:local
```

目标环境仍需单独准备：

- `docker-compose.yml`；
- `docker/.env`；
- 首次部署时使用的 `docker/initdb.sql`；
- 可访问的 PostgreSQL、Redis 和 Ollama。

## 8. 生产环境配置

生产环境至少设置：

```dotenv
JB_DEPLOYMENT_MODE=production
JB_SECRET_KEY=<至少32位的独立随机密钥>
JB_ALLOWED_HOSTS=agent.example.com
JB_HEALTHCHECK_HOST=agent.example.com
JB_DEBUG=false
JB_DB_PASSWORD=<数据库强口令>
JB_REDIS_PASSWORD=<Redis强口令>
JB_DEFAULT_PASSWORD=<首次登录强口令>
```

业务镜像构建完成后，可以直接使用镜像内的检查程序执行生产门禁；这样不需要在宿主机安装 Python，也不会通过 `source` 解析包含特殊字符的口令：

```bash
docker compose --env-file docker/.env run --rm --no-deps \
  --entrypoint /opt/venv/bin/python \
  app /opt/jb-agent-app/scripts/check-deployment-security.py --production
```

生产模式会启用安全 Cookie、HTTPS 重定向和 HSTS。必须在反向代理、Ingress 或负载均衡器终止 HTTPS，并向应用传递：

```text
X-Forwarded-Proto: https
```

不要把 `JB_ALLOWED_HOSTS` 配置为 `*`、`localhost` 或 `127.0.0.1`。生产环境中缺少必填项、使用开发默认口令、开启 DEBUG 或域名不合规时，业务容器会拒绝启动。

## 9. 常见故障处理

### 9.1 容器反复重启

```bash
docker compose --env-file docker/.env ps
docker compose --env-file docker/.env logs --tail=300 app
```

优先检查日志中的安全门禁、数据库连接、Redis 连接和 migrations 错误。不要仅凭端口开放判断数据库已经可用。

### 9.2 数据库连接失败

检查：

1. `JB_DB_HOST` 在容器内部是否可达；
2. 数据库名是否与初始化时的 `app_db` 一致；
3. `JB_DB_USER` 是否拥有目标数据库权限；
4. PostgreSQL 是否允许来自 Docker 网段的连接；
5. `vector` 扩展是否已经安装并启用；
6. 日志中的 migrations 是否全部成功。

容器访问宿主机数据库时不要把 `JB_DB_HOST` 写成 `127.0.0.1`。

### 9.3 Redis 连接失败

检查 Redis 监听地址、防火墙、发布端口、密码和数据库编号。`/healthz` 会实际执行一次 Redis 写入和读取，返回 503 时可结合日志判断。

### 9.4 Ollama 连接失败

```bash
curl -fsS <JB_OLLAMA_BASE_URL>/api/tags
```

检查事项：

- URL 是基础地址，没有重复追加 `/api`；
- 容器访问宿主机时使用 `host.docker.internal`；
- 远程 HTTPS 证书链受信任；
- 所需模型已经下载；
- 数据库中已有模型配置需要重新测试连接。

Ollama 在线不代表容器内向量服务在线，两者是独立组件。

### 9.5 健康检查返回 503

`/healthz` 任一依赖检查失败都会返回 503，但不会向响应暴露连接详情。查看业务容器日志，并依次检查 PostgreSQL、Redis 和容器内 `127.0.0.1:11636`。

### 9.6 页面打不开

- 确认访问的是 `http://localhost:8080/admin/`，不是仅访问根路径；
- 检查宿主机 `8080` 是否被占用；
- 检查容器端口映射是否为 `0.0.0.0:8080->8080/tcp`；
- 生产模式下必须通过正确配置的 HTTPS 反向代理访问；
- 查看浏览器网络面板和容器日志中的 404、502 或重定向信息。

### 9.7 容器停不下来或镜像删不掉

先区分镜像和容器：

```bash
docker ps -a --filter name=telecom-ai-agent
docker compose --env-file docker/.env down
```

只有停止并删除引用镜像的容器后，镜像才可以删除。不要为了删除镜像而清理 PostgreSQL、Redis 容器或它们的数据卷。

## 10. 交付验收记录建议

交付时建议记录以下信息，但不得记录明文口令：

| 项目 | 建议记录内容 |
| --- | --- |
| 代码版本 | Git commit SHA |
| 业务镜像 | 镜像名称、标签、镜像 ID、SHA-256 |
| 数据库 | PostgreSQL 版本、pgvector 版本、数据库名 |
| Redis | Redis 版本、数据库编号 |
| Ollama | 服务地址、Ollama 版本、已验收模型名称 |
| 部署入口 | 管理端、聊天端、健康检查正式地址 |
| 验收时间 | 首次启动和业务冒烟完成时间 |
| 验收结果 | 健康检查、登录、模型、知识库和对话结果 |

更细的构建参数和手动命令见 `docs/Docker手动打包与运行命令.md`；开发环境排障经验见 `docs/开发与运维排障手册.md`。
