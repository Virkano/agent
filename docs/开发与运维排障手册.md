# 开发与运维排障手册

本文记录本项目已经验证过的本地运行方式和常见故障诊断顺序。目标是先取得可复现证据，再修改代码或重启服务，避免重复踩坑。

## 一、统一命令入口

### Django

所有 Django 命令从仓库根目录 `/Users/zhaozhenchao/course/AI/Agent` 执行：

```bash
set -e
set -a
source .env.local
set +a
./.venv/bin/python apps/manage.py check
```

这四点缺一不可：正确工作目录、加载 `.env.local`、使用 `.venv`、依赖步骤失败即停。不要在 `apps/` 目录直接运行，也不要使用系统 Python。环境加载三行必须原样保留，尤其不能把 `set +a` 误写成会打印全部环境变量的裸 `set`；命令输出不得出现数据库或模型凭证。

常用验收命令：

```bash
./.venv/bin/ruff check <changed-python-files>
./.venv/bin/python apps/manage.py makemigrations <app> --check --dry-run
./.venv/bin/python apps/manage.py test <app> --keepdb --noinput
```

### 前端

前端命令在 `ui/` 目录执行：

```bash
pnpm exec eslint <changed-files>
pnpm run type-check
pnpm run build
```

不要从仓库根目录运行 `npm exec eslint`，否则可能绕过本地依赖并尝试联网安装包。

## 二、Docker PostgreSQL 连接排障

本地 PostgreSQL 由 Docker 启动。按下面顺序检查，不要只看到“连接失败”就修改数据库代码。

### 1. 容器是否运行

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}\t{{.Status}}'
```

当前开发环境预期容器名为 `telecom-ai-postgres`，宿主机 `5432` 映射到容器 `5432`。容器不存在时再检查 `docker ps -a` 和项目 Docker 启动方式。

### 2. 连接地址是否与运行位置匹配

- Django 运行在宿主机：数据库主机通常是 `127.0.0.1`，端口使用 Docker 映射端口。
- Django 运行在同一个 Compose 网络：数据库主机应使用服务名，不能使用 `127.0.0.1` 指向另一个容器。
- 连接参数以 `.env.local` 和 Django 实际加载结果为准。诊断输出只打印主机、端口、库名等非敏感项，不打印密码。

### 3. 数据库是否真正可用

优先让 Django 自己验证，因为这能同时验证环境变量、驱动、认证和目标数据库：

```bash
set -a
source .env.local
set +a
./.venv/bin/python apps/manage.py check
./.venv/bin/python apps/manage.py showmigrations
```

需要容器侧探测时，可在容器内运行 `pg_isready`。若端口可达但 Django 失败，继续区分认证失败、目标库不存在、驱动缺失和迁移不一致，不要把它们统称为“PostgreSQL 没启动”。

### 4. 迁移检查与应用

```bash
./.venv/bin/python apps/manage.py showmigrations <app>
./.venv/bin/python apps/manage.py migrate <app> --noinput
./.venv/bin/python apps/manage.py showmigrations <app>
```

应用前后都检查迁移状态。迁移文件生成后还必须执行 `makemigrations --check --dry-run`，确认模型没有遗漏变更。

### 5. PostgreSQL 加锁特例

错误：`FOR UPDATE cannot be applied to the nullable side of an outer join`。

根因通常是 `select_for_update()` 与指向可空外键的 `select_related()` 同时使用。正确处理是只在主表查询上加锁，需要的可空关联在锁定后按外键读取；不要为了绕过错误扩大锁范围。

### 6. 单业务镜像的中间件连接

当前根目录 `docker-compose.yml` 只定义 `app`，不会创建、拉取或删除 PostgreSQL/Redis 容器。Mac/Windows 上业务容器连宿主机现有中间件时，默认使用 `host.docker.internal`；Linux 通过 Compose 中的 `host-gateway` 映射保持同一配置。

验收顺序：

1. 先核对 PostgreSQL/Redis 已有容器、宿主机映射端口与实际账号库名。
2. 使用 env 文件传入凭证，不在命令行、文档或日志中展开密码。
3. 等容器进入 healthy，调用 `GET http://127.0.0.1:8080/healthz`；该端点会真实执行 PostgreSQL 查询、Redis 读写和容器内向量端口连接。
4. 再分别检查 `/admin/login`、`/chat/`、未认证 API 401、宿主机 Ollama `/api/tags` 和一次真实 `embed_query()`。
5. 使用 `migrate --check` 确认导入的历史 SQL 已由启动迁移补齐。

业务镜像仅对外映射 8080；本地向量服务只监听容器内 `127.0.0.1:11636`。精简镜像不保证存在 `ps`，进程核对可读取 `/proc/*/cmdline`；验收探针优先不落盘，不在组合命令中为清理临时响应追加强制删除。完整操作命令见 `docs/Docker手动打包与运行命令.md`。

## 三、本地模型与智能体报错排障

### Ollama

```bash
curl http://127.0.0.1:11434/api/tags
```

HTTP 200 只说明服务在线，还要确认返回列表中存在应用配置使用的模型。模型缺失时再执行拉取或调整配置。

### 本地向量模型

向量服务根路径可能设计为 404，因此下面的结果不能直接说明服务异常：

```bash
curl http://127.0.0.1:11636/
```

本地启动入口为 `scripts/start-local.sh local_model`。启动命令进入运行会话后，应等待日志明确显示 `127.0.0.1:11636` 正在监听，再做业务探针；端口未监听时，Web 侧 `embed_query()` 常表现为响应体 JSON 解析失败，不能误判成模型向量格式错误。

2026-09-22 M02 实测：Ollama 11434 在线不代表向量服务在线。真实知识库对话在 `embed_query()` 处返回非 JSON，检查发现 11636 未监听；启动 `scripts/start-local.sh local_model` 后，以数据库绑定模型 UUID 跑完整对话，获得 1 条引用和 `PASS` 审核。此类故障先查独立向量端口与实际模型调用，再查索引/阈值。

可靠检查方式是读取知识库绑定的模型配置，通过应用现有模型加载逻辑执行一次 `embed_query()`，同时校验返回向量非空及维度符合索引。模型端点要求 UUID 时必须使用数据库里的模型 ID，不能使用展示名称。Ollama `api/tags` 返回 200 只证明生成模型服务在线，不能替代独立 11636 向量服务的检查。

### 从页面报错定位链路

1. 先确认后端接口返回的是 401/403、业务错误还是 500。
2. 再检查知识库是否绑定可用向量模型、是否存在有效段落和向量。
3. 涉及生成模型时检查 Ollama 在线和目标模型存在。
4. 使用真实检索或对话链路复现；端口在线不能代替业务调用成功。
5. 依赖异常应保留可理解的业务错误或降级结果，不能把凭证、堆栈或内部话术暴露给用户。

## 四、服务状态判断

当前本地约定：

- 前端：`http://localhost:3000/admin/`
- 后端：`http://127.0.0.1:8080/admin/api/`
- Ollama：`http://127.0.0.1:11434/api/tags`
- 本地向量服务：端口 `11636`，必须调用实际模型端点验证

对需要鉴权的后端接口，未登录返回 401 可以证明端口、路由和鉴权链路已生效；不能因为不是 200 就判断后端未启动。

Vite 根地址 `http://localhost:3000/` 可能返回 404；管理端必须访问 `http://localhost:3000/admin/`。本项目的开发服务器绑定 IPv6 通配地址 `::`，同时兼容 `localhost` 的 IPv6 `::1` 和 IPv4 `127.0.0.1`。启动验收除了 curl 之外，还应分别执行 `curl -4`、`curl -6`，并在真实浏览器确认 `/admin/login` 首屏可见。

### 嵌套路由页面无法滚动

知识库详情的右侧布局使用 `overflow: hidden` 裁剪内容。新增长页面如果只有 `min-height: 100%`，内容超过视口后会被裁掉且没有滚动目标。页面根节点应同时设置：

```scss
box-sizing: border-box;
height: 100%;
min-height: 0;
overflow-y: auto;
```

修复后不能只确认元素存在，还要在真实浏览器从页面顶部滚动到底部，确认底部表格或操作区确实可见。

### 已知环境警告：ffmpeg

Django 命令当前可能出现 `pydub` 未找到 ffmpeg/avconv 的运行时警告。它不影响数据库、知识检索或本次评估功能；只有使用音频解码、转码或切分能力时才需要处理。届时先安装 ffmpeg 并确认 `ffmpeg -version` 可用，不要把该警告误判为 Django 启动失败。

### 浏览器验收登录态安全

真实浏览器验收需要鉴权时，不要把访问令牌直接传给会回显执行代码的浏览器 CLI，也不要把 storage state 提交到仓库。优先复用专用测试账号的隔离、限时登录态；必须临时签发时，应满足：

1. 令牌只用于本地地址和单次验收，不写入文档、截图文件名或脚本。
2. CLI 输出必须预先确认不会回显敏感参数；不确定时使用无回显的隔离驱动。
3. 验收结束立即关闭会话并按缓存版本精确撤销临时令牌，不能清空其他用户会话。
4. 若发生回显，立即记录安全事件、撤销令牌，并在确认撤销成功后继续交付。

本项目的接口权限装饰器同时读取 `request.user` 和 `request.auth.role_list/permission_list`。使用 DRF `APIClient.force_authenticate()` 做本地 API 验收时，只传用户会导致权限上下文为空；应注入最小测试角色上下文。统一响应类型是 `common.result.Result`（`JsonResponse`），不能按 DRF Response 读取 `.data`，应解析响应 JSON。

本项目没有安装 Django 默认 `auth.User`。本地 API 验收或临时认证脚本不要使用 `django.contrib.auth.get_user_model()` 假设默认用户模型存在，应使用项目用户模型 `users.models.User`，或直接复用对应测试夹具里的用户对象。

隔离浏览器不能复用人工登录态时，可以在系统临时目录生成权限为 `600` 的一次性 Playwright storage state；文件只能包含本地验收所需的令牌和工作空间，加载后立即精确删除。验收结束必须调用注销接口、清理角色/权限缓存、删除临时账号并关闭浏览器。不要用 `/dev/fd` 进程替换跨越 `npx` 包装器传递状态，也不要用 `rm -f` 或 `rm -rf` 清理临时目录；精确文件先做存在性检查，再用 `unlink <明确文件>` 删除并用 `test ! -e` 验证。

手工生成系统用户临时 token 时，认证类型枚举来自 `common.constants.authentication_type.AuthenticationType`，会话超时时间配置来自 `telecom_ai_agent.const.CONFIG`。写入浏览器 state 前先确认脚本不会打印 token；撤销时从 state 文件读取 token 后按 `Cache_Version.TOKEN` 的 key/version 精确删除，再删除 state 文件。

浏览器命令通常从 `output/playwright/<label>/` 执行，但 Django 登录态撤销命令仍依赖仓库根目录的 `.env.local` 和 `apps/manage.py`。撤销前必须切回仓库根目录，或对这两个路径使用已验证的绝对路径；不要在产物目录内沿用根目录相对路径。

### 浏览器验收的数据准备策略

粗粒度 V1 的浏览器验收应控制在必要范围：优先调用真实 API 构造实验、版本、评估、发布等状态，再用浏览器刷新页面，检查关键数字和状态、控制台错误、响应式布局及滚动到底。只有验收目标明确包含表单校验、下拉选择、确认框等交互时，才逐字段走完整 UI 链路。

接口准备数据时仍要经过鉴权和真实数据库，不能直接伪造前端状态。验收数据可以保留为演示样例；只有用户明确要求清理或数据会污染正式口径时，才按唯一名称或 ID 精确删除。

### 模型生命周期发布异常

模型版本发布和回滚按以下顺序核对：

1. 来源实验必须已经进入“已完成”，草稿或运行中实验不能注册版本。
2. 目标版本必须至少有一条通过准入阈值的评估记录；只修改版本状态不能绕过发布门禁。
3. 同一工作空间、同一注册模型名称同时只能有一个已发布版本；新版本发布时旧版本归档。
4. 回滚不是删除新版本，而是把已评估通过的历史版本重新设为已发布，同时写入包含来源版本、目标版本、原因和操作人的审计记录。
5. PostgreSQL 中切换状态时只锁版本主表，不把可空实验、在线模型等关系通过外连接带入 `select_for_update()`。
6. 外部 MLflow 等跟踪器应通过适配器接入；本地适配器不可用时不能阻断核心实验和版本状态机。

### 联调后端端口与 Vite 代理

本项目 Vite 开发代理固定指向 `http://127.0.0.1:8080`。重启 Django 时不要凭习惯使用 `8000`，应先检查 `ui/vite.config.ts` 的 `proxy` 目标。若页面接口统一返回代理 500、而 Django 没有对应请求日志，按以下顺序判断：

1. 直连 `http://127.0.0.1:8080/admin/api/...`，受保护接口返回 401 也能证明服务和路由已生效。
2. 再访问 `http://127.0.0.1:3000/admin/api/...`，确认 Vite 代理能转发。
3. 两者结果不一致时优先检查后端监听端口，不先修改业务代码。

新增 Django 应用、`include()` 路由或 `INSTALLED_APPS` 后，即使数据库迁移和独立 APIClient 已通过，使用 `--noreload` 启动的现有后端仍持有旧路由表。此时应只重启后端，再验证直连与 Vite 代理都从 404 变为受保护接口预期的 401/403 或业务响应。

使用 zsh 执行联调脚本时，URL 的 `?` 和 `&` 会参与 shell 展开，完整 URL 必须用单引号包裹；可选文件也不要使用可能无匹配的裸通配符，应先通过 `rg --files` 或 `find` 确认真实路径。zsh 的 `status` 是只读特殊参数，HTTP 返回码等临时变量应使用 `http_code` 这类业务化名称。若同类脚本错误连续出现，停止组合命令，先逐条验证最小命令再恢复编排。

### 平台监控探针与告警判断

- 数据库必须用 Django 当前连接执行 `SELECT 1`，避免探测到错误实例。
- Redis 使用短期、带工作空间前缀的缓存键做读写验证，不打印连接密码。
- Ollama 使用 `/api/tags`；向量服务的根路径 404 不作为离线依据，周期监控先做端口探针，专项排障再执行真实 `embed_query()`。
- 历史失败任务是审计数据，监控触发时先生成重试/回滚响应任务；不要在周期采集过程中直接执行破坏性回滚。
- 平台级告警通过通用通知的 `source_type/source_id/target_route` 接入右上角铃铛，禁止再建设模块内通知中心。

### 资源协调、优先级队列与租约恢复

- 资源分配以 PostgreSQL 中的资源池主表为串行化边界：事务内先锁资源池，再汇总活跃租约、检查剩余配额和互斥键，最后写任务、租约与追加事件。Redis 只能承担可丢失的加速或当前态，不能作为配额与审计事实来源。
- 优先级只作用于等待队列，排序规则为“优先级降序、入队时间升序”；运行中的租约不做意外抢占。后续需要抢占时必须新增显式策略、被抢占事件和恢复路径，不能静默改写任务状态。
- 请求编号和幂等键都按工作空间唯一。重复提交返回原任务；互斥键在提交时固化为快照，任一键被活跃租约占用时保留任务并写明等待原因。
- 租约到期不直接删除。显式回收时把租约标记为过期、原运行任务标记为失败、追加过期事件，再按队列规则尝试分配等待任务，保证故障恢复可追溯。
- 加锁查询只锁资源池或任务主表，不把可空用户、反向租约等外连接带入 `select_for_update()`。短任务编号使用 UUIDv7 的随机尾段；其时间前缀在同毫秒内高度相同，不能截取前缀作为唯一短码。
- 本地验收先通过 API 构造资源池和任务，再用页面检查配额地图、RUNNING/QUEUED 队列、冲突原因、租约倒计时和事件台账。页面与三个抽屉分别使用唯一业务类检查滚动，不用宽泛的 `[role=dialog]`。

### 标准事件、版本化 DAG 与人工节点

- 标准事件在持久化前先匹配已发布流程并校验必填载荷；任何匹配流程校验失败时整次接收失败，不能留下“已落库但没有运行”的半成品事件。事件 ID 和幂等键均按工作空间唯一，重复接收返回原事件及原运行实例。
- 流程版本保存事件类型、允许来源、事件契约和完整节点快照。发布新版本只把同编号旧发布版本归档；已经创建的运行始终引用原流程版本，不随草稿或后续版本变化。
- DAG 创建时必须校验节点编号唯一、依赖存在、不能自依赖且整体无环。只有全部依赖成功的节点才能就绪；同一轮中多个无互相依赖的节点可以并行申请资源。
- 除人工节点外，所有执行节点都通过资源协调服务生成独立调度任务，沿用资源池配额、优先级、互斥和幂等门禁。等待资源的节点不能直接改成运行中，应在显式推进时读取调度任务事实并同步。
- 人工节点不申请资源池，只接受通过或拒绝；运行、节点和人工操作均写顺序化追加事件。粗粒度 V1 的“完成/失败”按钮代表外部执行器回调契约，不能描述为已经实现真实异步执行器。
- 浏览器验收优先保留一条成功链路和一条等待人工链路；检查 Dashboard、DAG 详情、事件台账、主页面与独立抽屉滚动。API 和 Vite 代理请求均应返回 200，控制台不能出现业务错误。

### IVR 协议模拟与本地路由验收

- 标准 Django ASGI 入口不等于已经具备 WebSocket 业务服务器。项目未接入 Channels/Daphne 或生产 IVR 网关时，只能标记为 JSON `CONTRACT_REPLAY`，不得宣称真实长连接或电话线路已接通。
- PostgreSQL 保存会话与顺序化审计事件，Redis 只保存当前态快照；缓存不可用时应降级到数据库，不能丢失会话事实链。
- 来电号码只保存脱敏值，音频分片契约只保存引用和元数据；日志和审计记录不得写入原号码或音频二进制。
- 请求幂等键应绑定一个逻辑完成事件，重复请求先返回已有结果，再执行终态校验，保证网络重试不会重复写事件。
- 本地管理 API 的完整前缀是 `/admin/api`。探针前同时核对 Django `admin_api_prefix`、Axios `baseURL` 和 Vite 代理；受保护接口返回 401/403 可证明路由生效，404 才表示路径或加载异常。
- 新增本地管理页若要支持不带 `/admin` 的 `localhost:3000/<route>`，同步更新 Vite 的本地回退前缀并重启开发服务器。

Playwright CLI 使用 storage state 时必须先打开命名浏览器会话，再执行 `state-load`，最后用 `goto` 导航目标地址。反向顺序会因为会话不存在而加载失败；加载 state 后不要再次执行 `open <url>`，否则可能重新创建上下文并丢失刚加载的登录态。

当前 Playwright CLI 的 `run-code` 不接受裸 `await page...` 语句。页面导航完成后若没有异步交互依赖，不额外等待，直接执行 `snapshot`；滚动尺寸等只读检查使用 `eval`。不要把参考文档中的 `run-code` 示例未经验证直接拼入带 `set -e` 的验收链路。

当前 Playwright CLI 的 `screenshot [target]` 参数是元素目标，不是输出文件名。全页/视口截图直接执行无参 `screenshot`，产物会保存在会话工作目录的隐藏 `.playwright-cli/` 下；后续检索隐藏产物用 `find` 或 `rg --hidden --files`，不要依赖默认 `rg --files`。

### 变更操作风险评估与人工确认

- 风险判定不能只看累计分数。业务逻辑、一致性、大范围影响、跨系统且无回退等关键校验失败应设置关键标记并直接判红灯，即使累计分数尚未达到常规红灯阈值。
- 每次评估新增一个不可覆盖的修订版本，同时保存输入快照、原因、分数和评估人；操作主表只保存最新摘要，不能用更新主表替代历史审计。
- 红灯确认必须绑定当前评估版本，并快照确认时的风险级别和分数。重新评估后重新计算确认状态，旧确认记录保留但不能替代新版本确认。
- 确认请求的幂等键绑定一条变更操作：同一操作重放返回原确认结果，不重复写记录；跨操作复用同一键必须拒绝，避免把其他变更的人工结论错误返回。
- PostgreSQL 锁定时只对变更操作主表执行 `select_for_update()`，再独立读取可空 IVR 关系和评估记录，避免可空外连接加锁错误。
- 验收至少保留绿灯自动放行、黄灯提示、红灯待确认和红灯已决策四类样例，并验证页面与详情抽屉均可滚动到底。

### 变更提醒、执行门禁与质量报告

- 提醒/告知创建后先进入待发送状态，发送、确认、失败和重试按显式状态机推进；请求幂等键绑定一条变更操作，重放不能重复通知，跨操作复用必须拒绝。
- 站内发送统一进入右上角全局铃铛，不新增模块内通知中心。IVR、短信和人工渠道在真实网关未接入时只记录渠道、状态、时间和失败原因，不伪装成已真实触达。
- 开始执行前必须存在至少一条已发送或已确认的变更前通信；完成执行前必须存在至少一条已发送或已确认的执行中通信。开始、完成、终止均追加操作轨迹，不能覆盖历史动作。
- 通信或变更状态转移使用事务和主表锁。可空用户、IVR 会话等关系不要与 `select_for_update()` 外连接；先锁主表，再按需读取关系。
- 周期质量报告保存生成时的指标、每日趋势和操作明细快照，历史报告不随主表修改而漂移；日期下钻必须限定在报告周期内。
- CSV 导出使用 UTF-8 BOM；PDF 嵌入仓库 CJK 字体，所有时间先转业务本地时区。交付前生成真实文件，用 `file` 确认格式并逐页渲染检查中文、分页、长编号换行和页码。
- 长验收脚本应关闭 SQL 调试输出，并把数据构造、文件导出和最终汇总拆成可独立验证的短步骤，避免输出截断后依赖已经失效的终端句柄判断结果。

### 轻量双塔训练与召回

- 原有营销规则匹配只能作为标签构造或一条召回通道，不能作为 X01 双塔模型的替代实现。
- 特征快照必须同时包含用户塔和物料塔，且同一快照版本的哈希输入维度一致；训练前先检查两类数据均非空。
- V1 只把已上线且审批通过的营销活动生成物料向量，避免草稿或驳回活动进入在线候选。
- 训练需保存初始/最终损失、模型权重、物料向量和版本；发布新版本时归档旧版本，但保留历史产物和推理记录。
- 小规模本地基线可同步训练；扩展到生产数据量时应迁移到异步训练、对象存储和近似向量索引，不能在 Web 请求内运行大规模训练。

### 统一预演与申告模拟

- 预演场景定义“演什么”，预演实例记录“一次实际运行”；申告生成和导入必须绑定实例及版本化数据批次，不能直接把临时数据散落到业务表。
- 实例状态只允许按显式状态机推进：数据准备中完成校验后进入待启动，待启动后进入预演中，预演中才能完成；取消只适用于活动状态。状态转移使用事务并只锁实例主表。
- 数据生成、人工导入和状态变化都写入只追加事件。实例主表保存当前摘要，事件和批次保留事实历史，不能通过覆盖摘要替代审计轨迹。
- 申告 CSV 使用规范化英文表头和 UTF-8 编码，入口限制文件大小与行数。导入按行保存校验错误；部分错误批次标记为“部分通过”，有效行仍可使用，异常行不得计入执行数据门禁。
- 联系方式只保存脱敏值。未脱敏的人工导入值既要报告校验错误，也要在进入 `raw_data` 前再次脱敏，日志、错误摘要和导出均不得暴露原值。
- CSV 导出统一带 UTF-8 BOM，并对以 `=`、`+`、`-`、`@` 开头的单元格做公式注入防护；交付前用真实文件检查表头、行数、中文和校验错误列。
- UI 验收数据先用 API 构造，再在浏览器检查关键展示、筛选、抽屉、下载入口和滚动。浏览器当前工作空间必须从实际接口 URL 确认，不要沿用历史工作空间 ID 推断。
- 当前 Playwright CLI 列出网络请求使用 `requests`，查看单条详情使用 `request <index>`；若技能文档写成旧命令 `network`，以当前 `--help` 输出为准。
- Vue 模板会自动解包顶层 `ref`。需要把 `Ref<boolean>` 作为请求 loading 参数时，用脚本层无参包装函数承接模板事件，不要从模板直接传递该 ref。
- 预演场景库克隆是版本化复用，不是新建空库；默认继承来源库的场景、剧本、默认实例、流程模板、数据模型、权限和配置快照。实例详情里的场景库数量因此可能同时包含原库和克隆版本，测试断言应按业务继承关系核对，不要误判成重复数据。
- 从场景库创建场景执行时，执行记录需要保存 `library_id / library_name / library_version`，并回写场景库执行次数和最近执行时间；详情、dashboard 和列表口径要同时核对。
- `runserver --noreload` 不会自动加载新增 URL、应用或模型代码。改动路由后必须重启后端，并同时验证 `127.0.0.1:8080` 直连接口和 Vite 代理接口；旧进程返回 404 不能误判为路由实现缺失。
- 后端启动命令返回运行会话不等于 HTTP 已就绪。应用初始化可能需要加载词典和目录，应等待监听日志或对真实业务端点做有上限的短间隔重试；第一次 `Connection refused` 只能说明探测过早。
- 浏览器 TokenAuth 验收项目权限时，用户展示角色字段不能替代真实工作空间角色映射。临时验收账号必须在目标工作空间拥有实际 `WorkspaceUserRoleMapping`，验收后按缓存版本精确撤销令牌并用 `unlink` 删除明确的状态文件。
- 数据动态回溯生成的是事实快照：筛选条件、统一时间线、关键节点、指标差值、链路转移和校验摘要应一次保存，后续源事件变化不得改写历史回溯。空窗口也应保留 `EMPTY` 快照，不能以静默丢弃代替审计记录。
- 跨模型模拟记录查询应以各业务源表为事实来源，在服务层建立统一只读投影，不为“查询页”复制一套容易漂移的记录表。统一状态、进度、结果摘要和耗时只负责展示口径，详情继续返回源记录快照与追加式活动历史。
- 统一记录的详情地址必须同时携带记录类型和源记录 ID，避免不同表主键碰撞；“第几次执行”按同一预演实例、同一记录类型和发生时间稳定排序计算。关键字检索若覆盖所属实例编号/名称，测试也必须包含子记录因实例命中而返回的语义。

### 能力调用模拟

- 能力 Mock 是版本化隔离契约，不是生产接口代理。沙盒只读取保存的请求 Schema 和成功/失败模板，不发起真实网络请求；页面、响应元数据和验收文档必须明确这一边界。
- 模拟耗时通过调用记录的 `started_at`、`finished_at` 和 `latency_ms` 表达，不在同步请求中执行真实 `sleep`，避免验收超时样例拖慢接口线程。
- 每次调用保存能力版本快照、请求和响应，历史记录不可覆盖。重放必须新增记录并通过 `replay_of` 指向来源调用，不能修改原始结果。

### 通用指标、动态基线与派单

- 指标数据分为定义、数据源、采集批次和原始观测四层；批次逐行保存异常，异常行不进入基线和告警计算，不能用批次成功状态掩盖坏行。
- 动态基线按指标与维度键分别计算，只读取当前观测时间之前的历史样本；验收样例要先按均值和标准差核算所有中间点，避免普通波动提前触发。
- 规则主表只保存当前配置摘要，每次保存同步增加不可覆盖版本；合规失败的版本保留但不执行，告警固化实际命中的配置版本和基线版本。
- 值班派单固化当时的值班表、值班人和通知策略。同一告警恢复或关闭后再次越界是新的处置周期，必须创建新派单和新通知，历史工单不得重新打开覆盖。
- 指标派单统一进入右上角全局铃铛；页面验收至少覆盖八类主题、动态基线命中、值班指派、认领/处理/解决/关闭、铃铛通知和长页面滚动到底。
- 值班班次保存前必须检查结束时间晚于开始时间，并按工作空间、处理人和半开时间区间检测重叠；编辑时排除当前班次，停用班次不参与冲突门禁。
- 派单主表只保存当前处理人和状态摘要。创建、人工指派、转派、认领、开始处理、备注、解决和关闭分别追加事件，保存操作人、前后状态、说明和当时快照；转派后不得覆盖旧处理人事实。
- 数据源配置页面与后端都只接收非敏感定位和调度元数据。字段名命中 password、secret、token、api_key 或 credential 时直接拒绝，真实凭证必须进入独立受控凭证设施。
- `output/` 下的独立 Django 验收脚本不会继承 `apps/manage.py` 的模块路径；确需运行时应在导入 Django 前把仓库 `apps/` 目录加入 `sys.path`，脚本仍需先 `py_compile`，不得打印令牌或凭证。
- 请求幂等键绑定当前工作空间的一次逻辑调用：同键重试返回原记录，不重复增加调用序号和实例事件；调用序号按同一实例、同一能力稳定递增。
- 粗粒度请求 Schema 至少校验 `required` 字段；能力停用、场景不匹配或请求缺字段时必须拒绝执行，不能生成伪成功记录。
- warroom 只是调用记录的协同分组和统计维度，不是模块内通知中心。需告知用户的异常仍通过平台右上角全局铃铛承载。
- 能力调用必须同步写入预演实例的追加事件，并投影进 X26 统一模拟记录；实例详情、dashboard、X26 和 X27 的计数口径应一起验收。

### 故障模拟配置

- 故障配置是版本化预演契约，告警、超时、运行时段、拓扑和应急预案必须随版本一次保存；克隆生成新版本，禁止覆盖已发布或已绑定版本的历史内容。
- 配置校验必须逐项返回事实结果：告警校验编号/等级/比较符/阈值，超时校验 `step <= overall` 及动作，时段校验 `HH:MM`、时区和星期，拓扑校验节点唯一与链路端点，预案校验编号、名称和步骤唯一性。任一项失败都保留 `DRAFT`，不能应用到实例。
- 配置只能绑定同工作空间、同场景且未终态的预演实例。绑定时保存配置外键和完整不可变快照，后续配置归档不影响实例历史回放。
- 应用配置的事务只锁预演实例主表，再独立读取配置及其可空来源关系，避免 PostgreSQL 对外连接行执行 `FOR UPDATE`；幂等键只代表当前工作空间的一次应用请求。
- 创建、校验、克隆、应用和归档都写追加式配置事件，实例侧同步写应用事件；配置主表中的当前状态和校验摘要不能替代审计链。
- 真实验收至少保留一个五项通过版本和一个五项失败草稿，核对列表汇总、实例快照、绑定计数和详情事件；主页面、新建抽屉和详情抽屉都要滚动到底。

### 场景动态回溯

- X25 数据动态回溯负责指标、告警、操作、申告和舆情的业务事实时间线；X29 场景动态回溯负责流量帧、前后拓扑和节点状态镜像。两者可以引用同一预演事实，但必须分别保存不可变快照，不能用一个页面或模型混淆语义。
- X29 生成前必须验证实例已经应用含拓扑节点的 X28 故障配置。生成时一次固化流量帧、`topology_before`、`topology_after`、节点轨迹、镜像差异和汇总，并对稳定序列化后的载荷计算 SHA-256；后续源事实变化不得回写历史镜像。
- 能力失败/超时、活动告警和失败场景可以驱动节点及相邻链路进入降级状态；推导逻辑必须只依赖镜像内保存的事实和拓扑，列表统计、详情和播放工作台使用同一快照口径。
- 复杂 API 验收数据需要串联多张业务表时，使用单独的临时脚本文件并先做 `py_compile`，不要把包含嵌套字典、引号和 f-string 的长程序塞进 `manage.py shell -c`。脚本不输出凭证，验收后按明确路径删除并验证文件不存在。
- 同页存在多个 Element Plus 抽屉时，`[role=dialog]` 可能同时匹配已关闭的 Teleport 节点。滚动验收应使用当前功能的唯一业务类（如 `.scene-replay-detail-drawer`）定位可见抽屉，再检查内部 `.drawer-scroll`。
- 真实验收至少覆盖请求幂等、空窗口、节点 JSONB 筛选、播放推进、前后拓扑和详情滚动；临时登录态仍按隔离、限时、精确撤销执行。

### 故障上报模拟

- X30 只能绑定已应用 X28 故障配置的非终态实例。创建时同时固化上报模板版本、阶段定义、必填字段和初始 SLA，后续模板升级或归档不得改变历史上报。
- 上报状态按 `DRAFT → REPORTED → PROCESSING → RECOVERED → CLOSED` 转移；阶段推进与状态转移分开建模。升级只允许从低严重度升到更高严重度，推进、升级、恢复和关闭必须填写说明。
- 阶段截止时间从每次受理或推进的事实时间与模板阶段时长计算，列表和详情实时计算剩余/超时秒数。已恢复、已关闭记录不再参与超时统计，但保留原截止时间供审计。
- V1 附件只保存外部 `reference_id`、文件名、MIME、大小、说明、添加人和添加时间，不上传二进制。引用在同一上报内唯一，单个元数据声明大小仍需限制，日志不得输出真实文件内容或凭证。
- 每次创建、上报、受理、推进、升级、补充证据、恢复和关闭都追加独立事件，并同步写预演实例事件与 X26 统一模拟记录；主表当前状态和摘要不能代替事实链。
- 真实验收至少保留一条处理中的超时记录和一条已关闭记录，核对总数、活动数、超时数、证据数、实时倒计时、详情事实链、创建抽屉及主页面滚动。验收数据默认保留为演示样例。

### 处置进度模拟

- 流程模板定义可复用蓝图，流程运行记录一次实际演练。生成运行时复制模板步骤、名称、责任角色和计划耗时到不可变快照；后续修改模板不能改变历史运行。
- 流程运行使用显式状态机：待执行只能启动；执行中可以完成当前步骤、自动推进、阻塞、跳过、失败或取消；阻塞后只能恢复、失败或取消；完成、失败和取消均为终态。
- 自动推进不是后台定时器。粗粒度 V1 中它表示运行允许使用 `AUTO_ADVANCE` 动作一次完成当前步骤并进入下一步，便于稳定演示；真实时间驱动编排留给后续任务调度能力。
- 状态转移使用事务并只锁流程运行主表，再独立读取当前步骤。步骤保存开始/完成时间、耗时和备注；每次动作写追加事件，主表的状态、进度和摘要不能替代审计事实链。
- 列表、详情和 CSV 的当前步骤名称从运行时模板快照解析，不依赖现行模板，也不直接显示 `SLA_ASSESS` 等内部代码。CSV 使用 UTF-8 BOM，并继续防护公式注入。
- 生成流程前要求实例处于待启动或预演中，且至少存在一条校验通过的申告；异常申告保留用于审计，但不能满足流程生成门禁。
- 浏览器验收重点检查完成、执行中和阻塞三类状态，阻塞原因、当前步骤、进度和事件轨迹一致；列表页与流程抽屉均实际滚动到底，并确认相关请求 200、控制台 0 错误。
- 前端或后端热更新会使抽屉关闭并让旧元素引用失效。重载后先重新打开抽屉、获取新快照，再在当前 `[role=dialog]` 内定位 `.drawer-scroll`；不要把关闭状态误判成 Teleport 或滚动样式故障。

### 报告导出中文字体

PDF/Word 在开发机能生成并不代表中文可见。容器或 LibreOffice 渲染环境缺少系统 CJK 字体时，常见表现是中文为空白或方框。

- PDF 使用仓库内可分发的 TTF 并嵌入输出文件。
- DOCX 同时设置正文、标题、表格单元格的东亚字体，并嵌入字体部件；验证环境需要正确配置字体发现路径。
- 生成 HTML/PDF/DOCX 后先用 `file` 检查格式，再逐页渲染为图片检查中文、分页和表格，不以单元测试或文件大小代替视觉验收。

### 辅助模拟与多格式报告

- 可复现模拟必须同时固化输入因子快照、随机种子和业务结果快照。校验和只覆盖决定性业务结果，不包含创建时间、数据库主键等运行时字段；使用相同输入与种子复跑时应得到相同校验和。
- 网络、故障和流量因子分别保存分布、范围、单位、触发概率、是否触发、采样值与触发时刻。没有触发的因子也要保留配置快照，避免报告只显示结果而无法解释输入。
- 模拟结果至少包含分钟级原始点、基线、关键时刻、因子影响、前后均值/峰值/方差和异常窗口；X26 只做统一查询投影，不能代替 X31 的不可变结果快照。
- DRF 默认把 `format` 用作内容协商覆盖参数。业务导出接口不要再定义 `?format=pdf`，统一使用 `export_format=pdf|xlsx|json`，否则不受 renderer 支持的值可能在进入业务视图前直接返回 404。
- 报告同时提供精简版和完整版：精简版适合结论流转，完整版增加原始分钟数据。PDF 必须嵌入 CJK 字体并逐页渲染；Excel 必须实际解析工作表；JSON 必须反序列化并核对层级与原始点。
- 大表格跨页时给表头使用独立的白色文字 ParagraphStyle，不能只依赖 TableStyle 的 `TEXTCOLOR`，因为单元格 Paragraph 自身颜色会覆盖表格文字色；同时使用 `repeatRows=1` 复现表头。

### 调度时间的时区展示

Django 开启 `USE_TZ` 后，API 通常返回带时区的 ISO 时间。前端不能用 `replace('T', ' ').slice(...)` 直接显示，否则 Asia/Shanghai 的 09:00 可能显示为 UTC 01:00。应先构造 `Date` 或使用统一日期库转换到浏览器/业务时区，再格式化；验收时同时核对“配置执行时间”和“下次执行时间”。

### API 编排页面与 Vite 代理前缀冲突

本地前端把 `/admin/api` 代理到 Django。因此管理端 SPA 页面若命名为 `/api-orchestration`，完整地址 `/admin/api-orchestration` 也会命中该代理前缀，Vite 会在 SPA 回退之前将页面请求转发给后端，表现为页面 500 或后端 404。

排查与修复：

1. 分别用 `curl` 检查页面 URL、后端直连 API 和 Vite 代理 API，不把三者混为一个故障。
2. SPA 菜单路由改用不以 `/api` 开头的名称，例如 `/integration-orchestration`；后端业务 API 继续使用 `/admin/api/...`。
3. 同步更新 `ui/vite.config.ts` 的本地回退白名单并重启 Vite。
4. 验证页面入口返回 200，无凭证的后端直连和前端代理 API 均返回预期 401，再加载限时登录态进行业务验收。

API 契约本身应按不可变版本管理：发布新版只归档旧版，回滚基于历史快照生成新版。资产中只保存凭证引用，调用审计不保存真实凭证或鉴权上下文。

### 执行路径动态规划

- 条件表达式只保存来源、字段路径、白名单操作符和值；运行时逐段读取字典字段，禁止 `eval` 或任意脚本。节点输出条件的路径首段必须指向同一运行内的节点编号。
- 依赖策略区分“全部成功”“任一成功”“全部结束”。只有依赖全部进入终态后才能判断任一成功或跳过，避免并行分支尚未结束就错误释放下游。
- 备用节点必须标记为 `FALLBACK_ONLY` 并显式依赖故障来源节点。主路径成功时备用节点写“未激活跳过”事实；重试耗尽且选择降级时，原节点保留失败事实并标记已处理，备用节点再进入资源门禁。
- 每次资源申请使用包含尝试号的请求号和幂等键。节点主表只保存当前摘要；尝试表保存每次 dispatch、Trace、Span、输入、输出、错误、开始/结束时间与超时门限，重试不得覆盖上一次尝试。
- 节点超时时先让资源协调任务失败收口并释放租约，再记录超时与恢复事件，最后进入下一次尝试或备用路径。直接更新节点状态会留下活动租约并导致后续任务错误排队。
- 运行重放只能针对终态实例，并新建标准事件和运行 Trace；流程版本继续引用原运行绑定的历史版本，不能重新匹配当前发布版本。重放幂等键仍按工作空间唯一。
- 验收至少覆盖首次失败后重试成功、重试耗尽后降级成功、条件不匹配跳过、超时释放资源和历史版本幂等重放；演示数据优先通过服务/API 构造，浏览器只检查策略标签、尝试列表、事实链、重放入口和滚动。

### 指标趋势统计与事实下钻

- 趋势页不要再维护一套聚合事实表。查询原始观测，按观测时刻和维度键关联动态基线，再关联当时命中的规则版本、告警及派单事件，才能保证详情与曲线口径一致。
- “八类主题概览”和“当前指标趋势”是两层查询：设备、网元、时段、时间范围可共同约束两层；主题和指标只约束当前趋势。若先按主题过滤定义再计算主题卡，其余七类会被错误显示为零。
- 动态阈值必须使用观测时刻对应的基线版本计算，不能拿当前最新基线回填历史点；没有足够历史样本时明确返回空基线和空阈值。
- 下钻接口从观测 ID 出发，工作空间条件必须贯穿观测、基线、告警、派单和事件查询。批次原始快照、配置版本和追加事件只读展示，不根据现行规则重新推算历史事实。
- 趋势页浏览器验收至少选择一个有规则命中的主题，核对观测/基线/双阈值图、告警标记、详情抽屉底部、全局铃铛和请求状态；主题切换后同时确认未选主题总览没有被清零。

## 五、测试和交付门禁

每次功能收口依次确认：

1. Python Ruff 或目标语言静态检查通过。
2. Django `check` 通过，迁移一致且已在真实开发库应用。
3. 专项测试通过；涉及公共链路时再跑相关模块全量回归。
4. 前端 ESLint、类型检查、生产构建通过。
5. 使用真实服务做一次只读或事务回滚式业务探测。
6. 按验收约定检查样例数据已保留或临时数据已精确回滚，服务端口仍可用。
7. 在 `docs/测试/` 写清验收范围、命令、结果和已知非阻塞警告。

## 六、问题记录规则

- 操作一旦失败，先把现象、根因、修复和验证记录到 `.learnings/ERRORS.md`，再继续下一步。
- 用户纠正或业务语义踩坑记录到 `.learnings/LEARNINGS.md`。
- 同一问题具有跨功能复用价值时，提炼为 `AGENTS.md` 的短规则，并在本手册保留可执行步骤。
- 文档不得保存密码、访问令牌、模型密钥和解密后的凭证。
