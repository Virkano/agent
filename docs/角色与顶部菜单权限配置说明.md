# 角色与顶部菜单权限配置说明

## 1. 权限链路

平台按照以下顺序判断用户能否看到并访问功能：

1. 用户必须先被加入工作空间；未加入的工作空间不会出现在工作空间列表中。
2. 用户通过工作空间成员关系获得一个或多个角色。
3. 角色中的“查看”权限决定顶部菜单是否显示、路由是否允许进入、对应后端接口是否允许调用。
4. 智能体、知识库、工具和模型还可以继续配置资源级“查看/管理”权限；菜单权限不等于自动拥有所有具体资源。
5. 超级管理员和内置工作空间管理员保留管理入口；自定义角色只获得被明确勾选的菜单。

前端隐藏不是安全边界。顶部菜单、直接输入 URL 和后端 API 使用同一权限标识，未授权时分别表现为入口不显示、跳转到无权限页和接口返回 403。

### 当前新增页面的授权粒度

营销业务、运营分析、调度与演练下的新增 V1 页面采用“一页一权”的粗粒度模式。角色获得该页面的“查看”权限后，同时获得页面内的新增、编辑、删除、导出、审批、发布和执行等全部能力；没有该权限时，菜单、页面和接口全部不可访问。

智能体、知识库、模型、工具以及原有系统管理模块仍沿用细粒度权限和资源授权，不能把新增页面的“一页一权”规则套用到这些原有模块。

## 3. 给用户分配菜单的操作步骤

1. 使用平台管理员账号进入右上角头像菜单，点击“系统管理”。
2. 进入“角色”，创建自定义角色；普通业务人员建议继承“普通用户”，负责空间管理的人员才继承“工作空间管理员”。
3. 选中角色，打开“权限配置”，按照上表勾选需要显示的页面并保存。
4. 在角色的“成员”页添加用户，并选择该角色生效的工作空间；也可以在“工作空间 → 成员”中完成相同的角色分配。
5. 如果用户需要访问具体智能体、知识库、工具或模型，再进入“资源授权”配置具体资源的查看或管理权限。
6. 用户重新登录或刷新个人资料后，顶部菜单和工作空间列表按最新权限重新生成。

## 5. 常见误区

- 只把用户加入工作空间，不等于已经赋予业务菜单。
- 只授予顶部菜单，不等于自动拥有某个具体知识库或智能体；具体资源仍受资源授权控制。
- 对新增 V1 页面，“查看”就是整个页面的使用权，不需要再配置编辑、执行或导出权限。
- 不要通过前端隐藏替代后端鉴权；本项目的新增菜单已经同时接入路由和 API 权限校验。
- 自定义普通角色没有被勾选的新增菜单时，页面会隐藏；直接输入页面地址也不会绕过权限。
