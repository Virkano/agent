# 第 4 批：质检与值班专员演示稿

演示账号：`demo_quality_duty`  
目标工作空间：营销闭环测试-存量客户运营空间  
建议时长：8～10 分钟

## 开场与定位

登录后点击右上角工作空间名称，切换到“营销闭环测试-存量客户运营空间”。

> 营销任务已经开始产生对话、触达和转化数据。我的职责是检查客户实际收到的内容是否安全，监控业务和平台指标，并把异常通过告警、派单、处置和报告完整闭环。

## 1. 服务助手复核：先处理智能体发送前的安全结果

**进入路径**：顶部导航 → 展开`AI 能力` → 点击`服务助手复核`。

页面标题为“人工复核队列”。

**现场点击**：

1. 保持筛选为`待复核`，查看风险类型、处置动作、客户实际收到的答复、引用数和发生时间。
2. 找到一条待处理记录，点击右侧`复核`。
3. 在弹窗中选择`确认存在问题`或`排除问题`，填写核实依据。
4. 演示时优先取消弹窗并说明流程；确认是专用演示记录时再点击`提交结论`。
5. 切换到`全部记录`，展示已处理状态。

**页面作用**：复核通用服务助手回答的安全处置结果。此页只展示客户实际收到的安全答复，不展示被规则命中的敏感原文。

**推荐话术**：

> 合规检查发生在流式内容发送之前。高风险内容会被拦截、兜底或脱敏，再进入人工复核。复核结论只改变后台处理状态，不会把新内容重新发送给客户。

**离开前确认**：观众能看见风险类型与处置动作，并理解“复核记录”和“重新回复客户”是两件事。

## 2. 对话质检：复核营销对话并维护发送前策略

**进入路径**：顶部导航 → 展开`运营分析` → 点击`对话质检`。

**现场点击**：

1. 在页面上方查看`发送前质量策略`。
2. 依次指出`关闭`、`影子检测`和`灰度拦截`三种模式。
3. 使用状态、风险或任务筛选定位一条记录，点击右侧`处理`或`查看/复核`。
4. 在“回答复核与修订”抽屉中查看原回答证据、风险判断、修订版本和复核意见。
5. 关闭抽屉，查看规则效果区域中的已复核数、确认问题数和误报率。

**页面作用**：营销对话质检独立于通用服务助手复核，用于发送前规则灰度、人工确认与修订留痕。

**推荐话术**：

> 影子检测只记录命中，不拦截客户回答，适合新规则观察期；灰度拦截只作用于已选择且通过准入门槛的高风险规则。我们先积累人工复核结果，再根据准确率和误报率决定是否扩大拦截范围。

**现场注意**：不要为了演示直接把全局策略切成灰度拦截。策略变更要有样本、门槛和演示环境确认。

## 3. 营销运营监控：从任务态势发现业务异常

**进入路径**：顶部导航 → `运营分析` → `营销运营监控`。

**现场点击**：

1. 在顶部选择一条营销任务。
2. 选择 `7 天`、`30 天`或`90 天`统计周期，点击`刷新`。
3. 查看健康概览、趋势指标和问题清单。
4. 点击`告警规则`查看规则配置；返回后点击`同步告警`，说明业务异常如何进入统一告警链。
5. 在告警工作台打开一条已有告警，查看状态和处置结果。

**页面作用**：把营销任务的触达、响应、转化、质检和异常统一展示，帮助值班人员定位是业务效果问题还是质量风险。

**推荐话术**：

> 运营监控先回答“哪个任务出了问题”。时间范围和任务筛选影响当前趋势与问题清单；发现异常后再下钻到指标事实、告警或具体质检记录，而不是仅凭一张汇总卡片下结论。

## 4. 指标预警：从一个异常点追到派单闭环

**进入路径**：顶部导航 → `运营分析` → `指标预警`。

页面标题为“指标趋势与预警处置中心”。

### 4.1 趋势分析

**现场点击**：在`趋势分析`中选择主题、指标、设备、网元、时段和时间范围，点击`查询`；点击趋势图数据点或列表右侧`详情`。

**页面作用**：查看观测值、动态基线、关注/紧急阈值，以及该观测命中的告警和派单事实链。主题筛选只影响当前趋势明细，八类主题概览仍显示全局状态。

### 4.2 指标配置与预警规则

**现场点击**：依次打开`指标配置`、`预警规则`。

- 在`指标配置`查看指标定义和数据源。新增数据源只保存非敏感定位信息，不填写密码、令牌或 API Key。
- 在`预警规则`打开一条规则，查看固定阈值或动态基线、判断方向、生效时间和版本。

**页面作用**：指标定义说明“采什么”，规则说明“什么情况算异常”。规则每次保存生成新版本，已经触发的历史告警继续绑定当时版本。

### 4.3 值班与派单

**现场点击**：

1. 打开`值班台历`，查看班次和处理人。
2. 打开`派单闭环`，选择一条未关闭工单。
3. 点击查看处置记录；依次说明`指派/转派`、`认领`、`开始处理`、`追加备注`、`标记解决`和`关闭`的顺序。
4. 打开`采集批次`，查看总行数、成功行、异常行和批次状态。

**页面作用**：值班表确定异常由谁接手；派单保留每次状态变化与备注；采集批次保留原始观测进入系统的证据。异常行不进入执行门禁，但不会被静默丢弃。

**推荐话术**：

> 一个异常点不是一张孤立告警。平台能追到它来自哪个采集批次、使用哪版动态基线和规则、生成哪张工单、由谁在什么时间完成了什么动作。

## 5. 平台监控：区分业务异常与技术异常

**进入路径**：顶部导航 → `运营分析` → `平台监控`。

页面标题为“全维度监控与告警”。

**现场点击**：

1. 查看模型性能、数据质量、知识时效和系统资源四类监控卡片。
2. 点击`刷新`更新页面；`立即采集`只在演示环境需要新数据时使用。
3. 在`活动告警`中打开一条记录，查看级别、自动响应和最近触发时间。
4. 对已有演示告警说明`确认`、`标记恢复`、`重试响应`的适用场景。

**页面作用**：营销运营监控关注业务结果，平台监控关注支撑业务的模型、数据、知识和资源是否健康。

**推荐话术**：

> 如果转化下降，我们既要看任务策略，也要排查模型性能、知识是否过期、数据质量和系统资源。这里把四类技术信号统一采集，异常仍进入右上角全局告警铃铛。

## 6. AI 分析报告与全局铃铛：完成汇报和通知闭环

**进入路径**：顶部导航 → `运营分析` → `AI 分析报告`。

**现场点击**：

1. 在左侧报告库点击一份已完成报告，右侧查看指标快照和 AI 解读。
2. 点击`下载报告`，展示可导出 HTML、PDF 和 Word；现场可只展开菜单，不重复下载。
3. 点击`报告模板`查看模板版本。
4. 点击`报告订阅`查看按天、周、月生成的计划。
5. 点击`生成报告`，指出报告模板、营销任务和统计周期字段后取消。
6. 最后点击页面右上角`告警铃铛`，查看告警、派单或报告完成通知，并从通知进入对应业务页面。

**页面作用**：报告把零散指标和处置事实整理成决策简报；订阅负责定期生成；铃铛负责统一提醒，不替代告警、工单和报告本身。

**推荐话术**：

> 系统只保留一个全局通知入口。收到通知后点击进入真实业务记录：告警到告警页，派单到工单页，报告完成到报告中心。这样既减少重复模块，也保证处理仍发生在有审计的业务页面。

## 交接话术

> 到这里，回答安全、营销质检、指标预警、派单处置、平台监控和管理报告已经形成闭环。下一位调度与演练负责人会说明这些能力如何跨系统编排，以及正式上线前怎样验证资源、变更和故障处置能力。

## 现场异常处理

- `服务助手复核`菜单缺失：确认当前账号为 `demo_quality_duty` 且工作空间正确，再检查菜单读取权限；不要改用管理员掩盖问题。
- 指标趋势为空：先放宽时间范围并清除设备、网元和时段筛选；仍为空则使用已有观测详情或 V1 样例。
- 没有待处理告警：切换状态查看历史记录，不为演示制造真实异常。
- 报告生成中或失败：打开失败详情说明参数快照和重试机制，使用已完成报告展示下载结果。
