# 第 5 批：调度与演练负责人演示稿

演示账号：`demo_rehearsal_lead`  
目标工作空间：营销闭环测试-存量客户运营空间  
建议时长：10～12 分钟

## 开场与定位

登录后点击右上角工作空间名称，切换到“营销闭环测试-存量客户运营空间”。

> 前面已经完成了 AI 能力、营销执行和风险监控。当一个任务需要跨多个系统、争用共享资源，或者涉及上线割接和故障处置时，就进入我负责的编排、资源协调和预演环节。

## 1. API 编排：定义外部接口应该怎样被调用

**进入路径**：顶部导航 → 展开`调度与演练` → 点击`API 编排`。

页面标题为“API 编排与晓搭适配”。

**现场点击**：

1. 在接口资产列表选择一条已有记录，打开详情。
2. 在版本列表点击`版本差异`，查看新增必填字段、输出删除、类型、路径或方法变化是否构成破坏性变更。
3. 指出`创建新版本`、`发布此版本`和`基于此版本回滚`三个入口。
4. 查看调用审计；依次说明`成功调用`、`重试恢复`、`触发熔断`、`鉴权失败`、`Schema 失败`用于验证什么。
5. 点击`登记接口`，展示手工契约字段和“OpenAPI 3.x 导入”区域后取消，不保存新资产。

**页面作用**：统一管理外部接口的路径、方法、输入输出 Schema、参数来源、依赖、版本、发布和调用事实。

**推荐话术**：

> API 编排解决“外部能力怎么安全、稳定地调用”。契约变化不会覆盖旧版，发布和回滚都有版本事实。凭证只保存引用，调用审计不写入鉴权上下文或真实密钥。当前 V1 的重试、超时和熔断主要是 Mock 契约回放，只配置网关地址不代表已经完成真实晓搭直连。

**现场注意**：`触发熔断`会产生失败事实，只对专用演示接口使用；普通演示打开已有审计记录即可。

## 2. 事件编排：把一个事件拆成可追踪的 DAG 流程

**进入路径**：顶部导航 → `调度与演练` → `事件编排`。

**现场点击**：

1. 在`流程版本库`选择一条已发布流程，查看版本、事件类型和节点数量。
2. 指出`创建流程版本`和草稿上的`发布此版本`入口。
3. 点击`注入标准事件`，查看事件 ID、幂等键、来源和载荷字段后取消。
4. 在`运行实例与节点进度`点击一条运行，打开详情。
5. 查看`节点执行图`、`执行尝试与 Span`和`运行事实链`。
6. 对已有运行说明：运行节点可`完成`或`失败`，人工节点可`通过`或`拒绝`，终态流程可`按原版本重放`。

**页面作用**：API 编排定义单个接口；事件编排定义“发生什么事件后，哪些节点按什么依赖、条件、重试和备用策略执行”。

**推荐话术**：

> 标准事件只接收一次，相同事件 ID 或幂等键不会重复创建运行。流程发布前校验未知依赖、自依赖和环。每次节点尝试都有独立 Trace/Span，历史重放继续绑定原来的流程版本，不会偷偷使用后来修改的流程。

**离开前确认**：观众能看到一条事件、一张节点执行图和至少一条运行事件。

## 3. 资源协调：决定任务现在能不能执行

**进入路径**：顶部导航 → `调度与演练` → `资源协调`。

**现场点击**：

1. 在`资源池配额地图`打开一个资源池，查看总配额、已用配额和运行租约。
2. 在`实时调度棋盘`查看等待与运行任务的顺序。
3. 在`任务与租约台账`点击一条任务，查看优先级、所需单位、互斥键、排队原因和租约到期时间。
4. 展开任务详情中的`不可变调度事件`。
5. 指出顶部`新建资源池`、`提交任务`，以及资源池上的`回收过期租约`入口。
6. 对运行任务说明`完成并释放`、`标记失败`和`取消任务`的收口差异，不操作非演示任务。

**页面作用**：事件编排决定执行先后关系；资源协调判断配额、互斥条件和租约是否允许节点现在运行。

**推荐话术**：

> 资源分配以 PostgreSQL 资源池主表锁串行化，Redis 只是可降级优化。优先级只排序等待任务，不会暗中抢占正在运行的租约。过期租约也必须显式回收并保留事件，不能直接从数据库删掉。

**什么时候使用**：模型训练、报告生成、批量触达等任务争用 GPU、队列、号码或外部接口配额时。

## 4. IVR 与变更控制：验证通话契约和上线门禁

**进入路径**：顶部导航 → `调度与演练` → `IVR 模拟`。

页面标题为“IVR 与变更操作控制”。

**现场点击**：

1. 在会话列表选择一条已有记录，点击`查看与模拟`。
2. 查看通话阶段、消息、当前状态和审计事实。
3. 指出新建会话区域中的传输方式，说明 HTTP 与 WebSocket 契约回放的区别。
4. 继续向下查看变更评估、风险门禁、人工确认和通信状态。
5. 按顺序指出：查看评估版本 → 查看红/黄/绿门禁 → 确认变更前通信 → 绑定人工确认 → 开始执行 → 确认执行中通信 → 完成变更。

**页面作用**：IVR 部分验证话务消息和阶段契约；变更控制保证上线、割接或高风险操作在执行前经过版本化评估、门禁、确认和通信检查。

**推荐话术**：

> 当前没有接入生产 IVR 网关和 Channels/Daphne，所以 WebSocket 展示的是消息契约回放，不能宣称已经完成真实话务对接。通话审计事实保存在 PostgreSQL，Redis 只保存可降级当前态，来电号码只保留脱敏值。

> 变更执行前先固化风险输入和评估版本，关键校验失败直接判红灯。人工确认绑定具体评估版本，开始和完成前分别校验变更前通信与执行中通信，避免拿旧确认放行新变更。

## 5. 故障与场景预演：按一条实例贯穿全页面

**进入路径**：顶部导航 → `调度与演练` → `预演管理`。

页面标题为“故障与场景预演”。这是长页面，进入后按下面顺序向下滚动，不需要现场逐个新建全部对象。

### 5.1 选择预演实例

**现场点击**：

1. 先看顶部`统一预演控制链`，从左到右说明整个链路。
2. 在`申告模拟模板`选择一套模板，说明公众/政企客户的输入差异。
3. 在`预演实例`列表选择同一条演示实例，点击`进入预演`。
4. 顶部`下载导入模板`用于准备批量数据；`新建预演实例`用于创建独立演练容器，现场只展示表单后取消。

**页面作用**：实例是整次演练的边界，后续批次、流程、配置、场景、上报和审计都绑定同一实例。

### 5.2 处置流程与模拟数据

**现场点击**：

1. 滚动到`处置进度模拟`，按实例筛选，点击一条流程的`查看进度`。
2. 查看步骤快照和流程事件；指出`启动流程`、`完成当前步骤/自动推进一步`、`阻塞`、`跳过`、`标记失败`、`恢复执行`和`取消流程`。
3. 关闭详情后滚动到`数据模拟与趋势看板`，选择同一实例，点击已有批次的`查看趋势`。
4. 指出`新建数据模拟`和`导出数据`入口。

**页面作用**：处置流程保存“当时采用哪版模板、每一步叫什么、怎样推进”；数据模拟生成指标或舆情时序，用来验证规则、图表和处置链。

**推荐话术**：

> 流程主表只保存当前摘要，步骤状态和操作事件保留完整事实。列表和导出显示创建时固化的步骤名称，即使后来模板改名，历史演练也不会变化。

### 5.3 故障配置和五项门禁

**现场点击**：滚动到故障配置区域，打开一条配置详情；查看`配置门禁`、`故障拓扑`、`告警条件`、`超时与时段`、`应急预案`、`实例绑定`和`配置审计`。

**页面作用**：故障配置把告警、超时、时段、拓扑和预案五类条件固化成一个版本。五项门禁任一失败都不得应用到实例。

**推荐话术**：

> 配置应用后，实例保存不可变快照。后续归档配置或创建新版本，都不会改写已经开始的演练。红灯拦截是正确结果，不应该为了跑通演示而绕过。

**现场点击补充**：指出`克隆新版本`、`重新校验`和`归档版本`；不归档当前演示正在使用的配置。

### 5.4 动态回溯和故障上报

**现场点击**：

1. 在场景动态回溯区域打开已有镜像，查看`前后镜像差异`、`节点级回溯`、`流量回放事实`和 SHA-256。
2. 在故障上报区域打开一条记录，查看`分阶段上报进度`、`上报推进控制`、`证据引用`和`上报事实链`。
3. 指出新建回溯的`生成镜像`和新建故障上报的`创建草稿`入口，现场使用已有记录讲解。

**页面作用**：动态回溯固化故障前后拓扑、流量帧和节点轨迹；故障上报按阶段推进并计算 SLA，附件 V1 只保存受限元数据引用，不上传真实文件。

**推荐话术**：

> 回溯使用实例已经绑定的拓扑快照，每次生成独立镜像，不跟随源数据变化。故障上报只有绑定已应用故障配置的实例才能创建，状态和阶段分别推进，每次动作都追加事件。

### 5.5 场景执行和人工收口

**现场点击**：

1. 在场景库中选择一个已有场景，查看剧本步骤和历史执行。
2. 点击已有场景执行，查看`场景推进控制`、`数据注入快照`、`场景剧本步骤`、`场景总结`和`关联模拟告警`。
3. 指出`启动场景`、`完成当前步骤`、`跳过步骤`、`标记失败`和`取消场景`。
4. 在`人工工单`查看`受理 → 解决 → 关闭`的事件链。

**页面作用**：场景库沉淀可重复使用的剧本；每次执行固化所用版本和注入数据；工单负责收口无法自动解决的遗留事项。

## 6. 交付收口

**进入路径**：演示结束后点击页面右上角`告警铃铛`，展示编排、资源或预演产生的通知入口。

**推荐话术**：

> 整套业务逻辑最终以一个对外暴露 `8080` 的主镜像交付，包含前端、后端和本地向量服务。PostgreSQL、Redis 和 Ollama 通过配置连接外部服务。初始化 SQL 只幂等创建空业务库和必需扩展，表结构由 Django migrations 管理，不把本地账号、业务数据、口令或模型密钥打入镜像。

## 结束话术

> 今天看到的不是一组页面，而是五个角色围绕同一条事实链协作：先治理，再准备 AI 能力，再执行营销，然后监控处置，最后用编排和预演保证可靠上线。每一步都有工作空间、版本、快照、事件和审计支撑，所以既能说明业务价值，也能说清交付和治理责任。

## 现场异常处理

- 编排运行等待外部系统：展示契约版本、节点 Trace 和已有历史运行，不在现场连续重试外部服务。
- 资源任务长期排队：检查配额、互斥键和租约，不直接修改数据库状态。
- 预演门禁未通过：指出具体红灯项；这是正确拦截，修复前不得应用配置。
- 长页面找不到区域：先回到页面顶部确认选择的是同一实例，再使用页面标题逐段向下滚动，不在地址栏猜深层路由。
