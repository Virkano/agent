# 第 3 批：营销运营专员演示稿

演示账号：`demo_marketing_operator`  
目标工作空间：营销闭环测试-存量客户运营空间  
建议时长：10～12 分钟

## 开场与定位

登录后点击右上角工作空间名称，切换到“营销闭环测试-存量客户运营空间”。

> AI 工程师已经准备好模型、知识和智能体。我的职责是把这些能力放进客户经营流程：先定义场景，再组织活动和任务，然后生成推荐、执行触达并回收反馈。

## 1. 营销场景：定义业务规则和能力组合

**进入路径**：顶部导航 → 展开`营销业务` → 点击`营销场景`。

**现场点击**：

1. 在场景列表选择一条已有记录，点击查看或编辑。
2. 指出场景绑定的智能体、知识库和推荐策略。
3. 关闭详情后点击`客户画像模拟`，选择演示客户或填写最小画像条件，查看模拟结果。

**页面作用**：营销场景定义“在什么业务情境下，面向什么客户，使用哪套 AI 能力和推荐策略”。画像模拟用于上线前检查规则是否会命中预期人群。

**推荐话术**：

> 场景不是一段营销文案，而是业务策略入口。它把目标客户、智能体、知识库和推荐策略组合起来。正式创建活动之前先做画像模拟，可以提前发现规则过宽、过窄或匹配对象错误。

**离开前确认**：观众能看到一条场景及其关联能力，并看到画像模拟的输入和结果。

## 2. 营销活动：把场景变成有时间和目标的计划

**进入路径**：顶部导航 → `营销业务` → `营销活动`。

**现场点击**：

1. 打开一条已有活动，查看活动目标、时间范围、状态和关联场景。
2. 点击该活动的`版本历史`，查看不同版本和发布状态。
3. 点击`活动效果复盘与放量建议`，查看指标、结论与建议。

**页面作用**：活动承载阶段性经营目标。版本历史保证修改不覆盖已发生的业务事实；复盘页判断活动是否值得扩大范围。

**推荐话术**：

> 场景回答“怎么做”，活动回答“这一次为什么做、什么时候做、做到什么程度”。活动修改会形成版本，历史发布版本不会被覆盖；恢复历史配置也会创建一个新草稿，而不是改写过去。

**什么时候使用**：新品推广、存量客户促活、套餐升级、流失挽回或节日专项运营时。

## 3. 营销任务：从客户名单走到触达审批

**进入路径**：顶部导航 → `营销业务` → `营销任务` → 选择一条已有任务。

**现场点击顺序**：

1. 点击`营销客户名单`，查看任务覆盖的客户。
2. 指出`导入客户名单`入口，说明可按模板导入；演示时不重复导入。
3. 点击`生成触达批次`或打开`触达批次`，查看批次状态与目标人数。
4. 点击`审批待办与超时预警`，查看待审批批次、审批状态和超时提示。
5. 打开一条批次，点击`批次执行与复盘`，查看执行数量、成功/失败和原因。

**页面作用**：任务把客户、推荐结果和渠道执行组织成可审批、可分批、可追踪的业务单元。批次让大规模触达能够分段放量和及时止损。

**推荐话术**：

> 客户进入任务后，不会立刻群发。系统先形成名单和触达批次，再经过审批和门禁。批次执行后保留成功、失败和异常事实，便于复盘，不用当前状态覆盖历史过程。

**现场注意**：使用现有批次讲解；只有确认是演示数据时才点击实际执行或审批按钮。

## 4. 推荐引擎：讲清召回、融合和精排

**进入路径**：顶部导航 → `营销业务` → `推荐引擎`。

页面标题为“召回与精排推荐引擎”。

**现场点击顺序**：

1. 打开`TopK 推理`标签，选择演示客户并查看双塔召回候选。
2. 打开`多路融合`，查看向量召回、规则或其他通道如何合并与去重。
3. 打开`精排 TopN`，查看候选在精排前后的名次和最终推荐理由。
4. 打开`效果监控`，查看点击、转化、负反馈和质量指标。
5. 指出顶部`精排策略`、`融合配置`、`生成特征快照`和`启动训练`按钮，说明用途，不在正式演示中临时训练。

**页面作用**：召回阶段追求“尽量找到可能合适的内容”，融合阶段合并不同来源，精排阶段追求“把最适合当前客户的内容排在最前”，反馈再回到训练和策略调整。

**推荐话术**：

> 双塔模型不是聊天模型，它用客户特征和内容特征快速计算相似度，适合从大规模候选中召回 TopK。之后系统融合多路候选，再用精排模型重排成 TopN。点击、转化和负反馈会作为效果证据，但单次反馈不会直接覆盖线上模型。

**离开前确认**：同一客户至少能看到一组候选和精排结果，能指出精排前后的顺序变化。

## 5. 触达与跟进：把推荐结果闭环成业务结果

**进入路径**：回到顶部`营销业务` → `营销任务` → 打开刚才的任务。

**现场点击**：

1. 点击`记录触达结果`，查看渠道结果、失败原因或客户响应字段；演示时优先打开已有记录。
2. 点击`待跟进队列`，打开一条待跟进客户。
3. 点击`记录人工跟进`，查看跟进方式、备注和下一步动作。
4. 点击`确认转化结果`，说明成交、未转化或继续跟进如何回写。
5. 最后点击`任务经营看板`，查看覆盖、触达、跟进和转化指标。

**页面作用**：把推荐从算法结果变成可验证的业务结果。触达、人工跟进和转化事实会反向支持活动复盘、推荐监控和后续优化。

**推荐话术**：

> 平台的闭环不是“生成了一条推荐”就结束，而是继续记录有没有触达、客户有没有响应、是否需要人工跟进、最后有没有转化。只有这条链完整，推荐效果才有真实依据。

## 交接话术

> 到这里，场景、活动、客户、推荐、触达、跟进和转化已经串成营销闭环。下一位质检与值班专员会检查内容是否合规、效果是否异常，以及异常发生后能否及时告警和派单。

## 现场异常处理

- 页面数据为空：先检查右上角是否切到营销闭环工作空间，再检查任务和活动筛选条件。
- 推荐结果为空：检查客户是否有特征快照、策略是否启用、候选池是否有数据；现场改用已有推理记录讲解。
- 批次不能执行：通常是审批、通信、配置或其他门禁未满足。保留失败信息并解释门禁，不直接绕过。
