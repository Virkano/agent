# 按角色分批演示手册

版本日期：2026-09-29

这套手册把平台全功能拆成 5 批，每批由一个独立演示账号完成。五个人围绕同一条业务链接力讲解，不把页面讲成互不相关的菜单。

## 一、角色与账号

| 批次 | 角色 | 演示账号 | 主要工作空间 | 讲解主题 | 建议时长 |
| --- | --- | --- | --- | --- | ---: |
| 1 | 平台管理员 | `demo_platform_admin` | 默认空间 | 平台、组织、权限与审计 | 6～8 分钟 |
| 2 | AI 与知识工程师 | `demo_ai_engineer` | 默认空间 | 模型、知识、工具和智能体 | 10～12 分钟 |
| 3 | 营销运营专员 | `demo_marketing_operator` | 营销闭环测试-存量客户运营空间 | 场景、活动、任务、推荐与触达 | 10～12 分钟 |
| 4 | 质检与值班专员 | `demo_quality_duty` | 营销闭环测试-存量客户运营空间 | 复核、质检、指标、告警、工单与报告 | 8～10 分钟 |
| 5 | 调度与演练负责人 | `demo_rehearsal_lead` | 营销闭环测试-存量客户运营空间 | 编排、资源协调、变更和故障预演 | 10～12 分钟 |

密码不写入仓库，仅保存在本地 `.local_runtime/demo-presenter-accounts.txt`，文件权限为 `0600`。

## 二、怎么读每份讲稿

每个步骤都按以下顺序编排：

- **进入路径**：从顶部导航开始，说明要展开哪个菜单、点击哪个页面。
- **现场点击**：现场实际点击的按钮、标签页或列表行。
- **页面作用**：说明这个页面解决什么问题，避免只报菜单名称。
- **推荐话术**：可以直接照着讲的内容。
- **离开前确认**：在切到下一页前，观众应该看到什么结果。

顶部导航的固定规则如下：

- `首页`、`智能体`是一级入口，直接点击。
- `AI 能力`中包含知识库、模型、工具和服务助手复核。
- `营销业务`中包含营销场景、营销活动、营销任务和推荐引擎。
- `运营分析`中包含营销运营监控、对话质检、AI 分析报告、指标预警和平台监控。
- `调度与演练`中包含 API 编排、事件编排、资源协调、IVR 模拟和预演管理。
- `系统管理`位于顶部`更多`菜单中，进入后再使用左侧菜单切换用户、角色、授权和日志。
- 工作空间从页面右上角切换。菜单缺失时先核对账号和工作空间，不要临时换成管理员账号掩盖权限问题。

## 三、接力主线

1. 平台管理员划定工作空间、人员和权限，保证后续操作有边界、有记录。
2. AI 与知识工程师接入 LLM、Embedding 和 Reranker，处理资料，用检索评估校验召回与精排，再组装成智能体。
3. 营销运营专员选择客户、活动和任务，通过召回与精排生成个性化推荐，完成审批、触达和反馈。
4. 质检与值班专员对对话和营销内容做质检，从运营指标中发现异常，通过告警、派单、全局铃铛和 AI 报告形成处置闭环。
5. 调度与演练负责人把多系统调用编成流程，协调并发资源，在上线或割接前进行变更检查、故障模拟和场景回溯。

统一串词：

> 管理员给出可治理的边界，AI 工程师交付可使用的能力，营销人员把能力用到客户经营，值班人员保证效果和风险可控，演练负责人保证复杂执行和正式上线可验证。

## 五、演示前统一准备

- 确认 PostgreSQL、Redis、后端 `8080`、管理端、Ollama `11434` 和向量服务均可用。
- 确认 Ollama 中至少有一个 LLM，知识库绑定的 Embedding 模型能完成真实向量请求。
- 五个账号各自使用独立浏览器会话预先登录，并切换到讲稿指定工作空间。
- 预先打开各角色第一个页面，现场不展示密码，也不在地址栏手输深层路由。
- 默认空间展示 AI 资源；营销闭环空间展示客户、活动、任务、推荐、指标和预演数据。
- 优先使用已有样例详情；需要新建时只做一条最小记录。验收数据可以保留。
- 准备一个正常问题、一个无引用问题和一个可触发合规规则的内容，分别展示正常、兜底和拦截路径。
- 涉及“发布、执行、熔断、故障注入、关闭工单”的动作，先用已有记录讲解；确需现场点击时使用专门的演示数据。

## 六、开发环境重建账号

仅在演示数据库中执行：

```bash
set -e
set -a
source .env.local
set +a
./.venv/bin/python apps/manage.py seed_demo_presenters \
  --primary-workspace-id default \
  --business-workspace-id 01a0560c-e867-7cd1-a58b-e1a736996d0a \
  --rotate-passwords
```

不加 `--rotate-passwords` 时，命令只幂等刷新角色、权限和资源授权，不改变现有密码。更换数据库后，应先从工作空间列表取得实际 ID，不能沿用本地样例 ID。

## 七、权限边界与验收状态

- 平台管理员在系统层绑定 `ADMIN`，并在演示涉及的每个工作空间绑定 `WORKSPACE_MANAGE` 和 `USER`，兼容 V1 中仍按工作空间角色判断的业务接口。
- AI 与知识工程师拥有模型、知识库、工具和智能体管理权限，不负责平台级用户管理。
- 营销运营专员负责营销业务数据，不执行模型发布和系统配置。
- 质检与值班专员拥有服务助手复核、监控、指标和处置所需权限，不负责营销活动发布。
- 调度与演练负责人因事件编排、资源协调和预演写接口的现有门禁，需要工作空间管理级权限；这是当前 V1 粗粒度边界，后续可继续拆成变更审批人、编排员和演练员。

2026-09-28 已使用 5 个账号完成真实登录和 46 项代表性菜单 API 冒烟，结果为 46/46 通过。后续修改角色、权限常量或接口门禁后，应重新执行相同范围的真实接口验收，不能只核对权限数量。
