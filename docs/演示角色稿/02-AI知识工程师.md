# 第 2 批：AI 与知识工程师演示稿

演示账号：`demo_ai_engineer`  
目标工作空间：默认空间  
建议时长：10～12 分钟

## 开场与定位

登录后点击右上角工作空间名称，确认已进入“默认空间”。

> 管理员已经给出工作空间和资源权限。我的职责是把原始模型和企业资料变成可调用、可检索、可评估、可回滚的 AI 能力，再把这些能力组装成业务可以直接使用的智能体。

## 1. 模型：先分清生成、向量和精排

**进入路径**：顶部导航 → 展开`AI 能力` → 点击`模型`。

**现场点击**：

1. 在模型列表查看已有供应商和模型，打开一条本地 Ollama 模型配置。
2. 返回模型页，点击`模型生命周期`。
3. 依次打开`自动训练流水线`、`实验管理`、`版本与发布`、`发布审计`标签页。

**页面作用**：模型页管理基础连接和模型类型；生命周期页管理从训练实验到版本发布的过程。

**推荐话术**：

> LLM 负责理解和生成，Embedding 把问题与资料转换成向量，Reranker 对召回候选做二次排序。接口能调用只说明模型在线，只有经过实验、评估和版本发布，才说明它适合稳定使用。

**什么时候使用**：首次接入模型、切换供应商、升级版本、效果退化或需要本地化部署时。

**离开前确认**：能够看到至少一个 LLM，以及知识库实际绑定的 Embedding 模型；现场不改 API 地址和凭证。

## 2. 知识库：从文档处理到检索验收

**进入路径**：顶部导航 → `AI 能力` → `知识库` → 点击一个已有知识库卡片进入详情。

### 2.1 文档与基础知识维护

**现场点击**：在知识库详情左侧依次点击`文档`、`问题`、`术语库`。

- `文档`：打开一份已有文档，再查看分段，说明原文如何拆成可检索内容。
- `问题`：查看预设问题，说明高频问法可以直接维护。
- `术语库`：查看一个术语及解释，说明企业专用词如何统一口径。

**推荐话术**：

> 上传文件只是第一步。平台还要保留原文、切分结果、问题和术语，后续检索效果不好时才能定位是资料、分段、向量还是排序的问题。

### 2.2 命中测试与检索评估

**进入路径**：保持在该知识库详情，左侧点击`命中测试`，随后点击`检索评估`。

**现场点击**：

1. 在`命中测试`输入准备好的问题，执行一次测试并展开结果，查看召回片段与分数。
2. 在`检索评估`选择已有评估集或评估记录，点击运行或打开结果详情。
3. 对比召回数量、阈值、精排前后顺序以及最终引用。

**页面作用**：命中测试解决单个问题的快速诊断；检索评估用一组标准问题比较不同配置，判断整体召回和精排质量。

**推荐话术**：

> 召回负责从大量资料中尽量找全候选，精排负责把最相关的内容放到前面。这个页面是知识工程的验收页，不是另一个聊天页。用户反馈答非所问时，我们先在这里复现，再决定调分段、阈值、召回数量还是精排模型。

**离开前确认**：现场至少展开一条结果，让观众看到“问题—候选片段—分数/名次”的关系。

### 2.3 ETL 与索引版本

**进入路径**：知识库详情左侧 → `ETL 与索引版本`。

**现场点击**：选择一条已有批次，查看处理状态、异常行和索引版本；只讲解版本发布或回滚入口，不临时重建全部索引。

**页面作用**：把资料清洗、切分、向量化和索引发布串成可追踪批次。正式更新生成新版本，历史版本不被覆盖。

**推荐话术**：

> 知识更新不是直接覆盖线上索引。每次处理都对应一个批次和一个版本，出问题时可以知道是哪批资料、哪种配置造成的，也能回看历史结果。

## 3. 工具与 API 编排：让智能体能执行业务动作

**进入路径一**：顶部导航 → `AI 能力` → `工具`。

**现场点击**：打开一个已有工具，展示名称、输入参数、输出定义和测试入口。

**进入路径二**：顶部导航 → `调度与演练` → `API 编排`。

**现场点击**：在“API 编排与晓搭适配”中选择一个已有接口资产，打开版本详情；查看契约、版本差异、发布审计和调用记录。

**页面作用**：知识库解决“知道什么”，工具和 API 解决“能做什么”。接口契约定义参数和依赖，版本记录保证变更可以审计与回退。

**推荐话术**：

> 智能体调用业务系统时，不直接把密钥写进配置，而是保存凭证引用。当前 V1 的调用演示主要是 Mock 契约回放，用来验证参数解析、重试、超时和熔断事实；只配置网关地址不代表已经完成真实晓搭直连。

**离开前确认**：观众能看到至少一个接口版本和一条调用审计，不展示任何真实 API Key、JWT 或 OAuth 密钥。

## 4. 智能体设置：把模型、知识和工具组装起来

**进入路径**：顶部导航 → 直接点击`智能体` → 点击一个已授权的智能体卡片 → 详情左侧`设置`。

**现场点击**：

1. 在设置页指出提示词、模型、知识库、工具和指定兜底答复的位置。
2. 不修改现有配置，只说明保存后会形成哪一层能力组合。
3. 左侧依次打开`概览`、`应用接入`、`对话用户`和`对话日志`。

**页面作用**：

- `设置`：决定智能体使用什么模型、知识和工具，以及没有可靠引用时怎么回答。
- `应用接入`：提供业务系统接入信息与发布后的调用方式。
- `对话用户`：控制哪些终端用户或用户组可以使用这个智能体。
- `对话日志`：回看真实问题、回答、引用和执行过程，用于追踪效果。

**推荐话术**：

> 智能体是能力组装层。它本身不是一个新模型，而是把模型、知识库、工具、提示词和安全策略组合成面向某类业务的服务。我的权限限定在已授权智能体内，可以维护设置和对话用户，但不等同于平台管理员。

## 5. 对话验证：用一问一答走完 AI 链路

**进入路径**：在智能体详情中进入`概览`或页面提供的调试/预览区域。

**现场点击**：

1. 输入准备好的正常问题并发送。
2. 等待回答完成，展开引用来源。
3. 切换到`对话日志`，找到刚才或已有的同类记录，查看问题、回答状态和引用。

**页面作用**：验证“用户问题 → 智能体编排 → 知识召回 → 精排 → 模型生成 → 合规检查 → 流式返回 → 日志审计”的完整链路。

**推荐话术**：

> 回答不是模型凭空生成。平台先找知识、再做排序、然后生成答案，并在内容发送前完成通用合规检查。审计只保存规则版本、风险类型、引用 ID、内容哈希和复核标记，不保存命中的敏感原文。

**离开前确认**：回答完成且能看到引用；若使用无引用问题，应展示智能体配置的指定兜底答复。

## 交接话术

> 现在已经交付了一套可调用、可检索、可评估、可回滚的 AI 能力。下一位营销运营专员不需要理解向量和模型细节，他只需要把这些能力用到真实的客户、活动和任务中。

## 现场异常处理

- Ollama 不可用：用 `GET http://127.0.0.1:11434/api/tags` 确认服务和模型；现场改用已保存的评估与调用记录讲解。
- 知识检索失败：向量服务根路径返回 404 不能判定离线，应以知识库绑定模型的真实端点或一次 `embed_query()` 为准。
- 智能体设置或对话用户提示无权限：先确认进入的是已授权智能体，再分别检查资源级读取、编辑、对话用户读写权限，不临时提升为管理员。
