# 新增功能操作日志接入规范

本文用于后续新增页面和接口时统一接入全局“日志管理”，避免出现操作无记录、日志中英文混杂或日志泄露业务数据的问题。

## 1. 需要记录的操作

必须记录：

- POST、PUT、PATCH、DELETE 等新增、修改、删除操作；
- 导入、导出、下载、审批、发布、执行、训练、触达、回滚和状态推进；
- 会改变清理策略、订阅人、权限、配置或运行状态的动作。

普通列表和详情 GET 默认不写通用操作日志。GET 如果用于下载、导出或触发业务动作，仍必须记录。敏感主数据读取按专用读取审计规则处理，不能用通用日志代替。

## 2. 接入方式

接口统一使用 `common.log.log.log`：

```python
@has_permissions(*module_permissions)
@log(menu="营销活动库", operate="提交营销活动审批")
def post(self, request, workspace_id, campaign_id):
    ...
```

要求：

1. 权限装饰器放在日志装饰器外层，未通过权限校验的请求不能冒充已授权业务操作。
2. `menu` 使用用户在顶部导航或页面看到的中文模块名。
3. `operate` 使用“动词 + 业务对象”的中文描述，例如“发布模型版本”，不能只写“操作”“处理”。
4. 工作空间接口必须让日志取得真实 `workspace_id`。
5. 无法使用装饰器的回调才使用 `record_log()`，并遵守相同字段规则。

## 3. 数据最小化

全局操作日志只允许保存：

- 操作者 ID 和角色；
- 工作空间 ID；
- HTTP 状态、IP、路由模板；
- 请求体字段名和查询字段名；
- 操作对象的字段名集合。

禁止保存请求值、响应正文、手机号码、邮箱、客户信息、密码、Token、API Key、模型密钥或解密后的凭证。自定义 `get_details`、`get_operation_object` 也不能绕过本规则。

## 4. 中文显示与历史数据

- 新接口直接使用中文菜单和中文操作名。
- 旧接口仍传入英文标签时，由 `common.log.labels` 在入库前转换为中文。
- 已存在的历史英文日志不直接更新，避免改写审计事实；日志列表和 Excel 导出通过同一映射显示中文。
- 新发现英文标签时，必须同步补充映射和自动化测试。

## 5. 交付检查

后端至少执行：

```bash
set -e
set -a
source .env.local
set +a
./.venv/bin/python apps/manage.py test \
  common.test_operation_log_coverage \
  common.test_master_data_audit \
  --keepdb --noinput
```

验收项目：

| 场景 | 预期 |
| --- | --- |
| 新增模块写操作 | 全部带全局日志装饰器 |
| 导入、导出、下载、审批、发布、执行 | 全部有中文操作记录 |
| 成功或异常 | 记录对应状态，不影响业务异常传播 |
| 历史英文日志 | 列表和 Excel 导出显示中文 |
| 最小操作者数据 | 用户名缺失时可显示和检索操作者 ID |
| 敏感字段 | 日志只出现字段名，不出现字段值 |

前端修改全局日志页后，还必须在 `ui/` 目录执行目标文件 ESLint、`pnpm run type-check` 和 `pnpm run build`。
