# 新增功能权限接入与验收规范

本文是本项目后续开发新增页面、接口和导航时必须执行的权限检查清单。目标是避免再次出现“菜单能看到但接口 403”“菜单隐藏但直接 URL 可以进入”“同一个权限可以跨工作空间使用”等不一致问题。

## 1. 当前权限策略

### 1.1 新增 V1 业务页面

营销业务、运营分析、调度与演练等本项目新增页面采用“一页一权”模式：

- 每个页面只定义一个 `<MODULE>_READ` 权限。
- `READ` 同时代表菜单可见、页面可进入和页面内全部功能可操作。
- 页面内的新增、修改、删除、导出、审批、发布、训练、触达和演练接口均复用这个 `READ` 权限。
- 当前不要为这些页面另建 `EDIT`、`EXECUTE`、`DELETE`、`EXPORT` 等权限，除非产品方明确要求调整权限粒度。

### 1.2 原有平台模块

智能体、知识库、模型、工具和系统管理继续使用原有细粒度权限：

- 菜单查看权限只决定入口和基础读取能力。
- 创建、编辑、删除、导出等动作继续校验各自权限。
- 智能体、知识库、模型和工具还必须校验具体资源的 `VIEW` 或 `MANAGE` 授权。

不得因为新增 V1 页面采用粗粒度权限，就放宽原有平台模块的权限边界。

## 2. 新增页面必须同步完成的事项

### 2.1 后端权限定义

1. 在 `common.constants.permission_constants.Group` 中增加页面业务组。
2. 在对应 `WorkspaceGroup` 下登记所属顶部菜单分组。
3. 在 `PermissionConstants` 中增加唯一的 `<MODULE>_READ`。
4. 补充权限树使用的中英文名称，确保角色配置页显示业务名称而不是内部代码。
5. 默认只授予系统管理员；内置工作空间管理员按照现有工作空间默认规则获得权限。普通角色必须显式勾选。

### 2.2 后端接口鉴权

1. 页面下所有 API 必须使用同一个工作空间级 `READ` 权限。
2. 基于 `APIView` 的整组接口优先继承 `WorkspacePermissionMixin`。
3. 已使用函数装饰器的接口通过 `workspace_menu_permissions()` 生成统一权限元组。
4. 权限必须包含当前 `workspace_id`，不能只比较不带范围的权限字符串。
5. 不得仅依赖前端隐藏按钮或菜单；未经授权的真实接口请求必须返回 HTTP 403。

### 2.3 前端权限接入

1. 在 `ui/src/utils/permission/data.ts` 增加与后端完全相同的权限字符串。
2. 顶部路由的 `meta.permission` 必须引用该权限。
3. 使用工作空间菜单权限公共方法，同时兼容系统管理员、内置工作空间管理员和自定义角色权限。
4. 子路由没有单独权限时，路由守卫必须继续检查父菜单及 `activeMenu` 指向页面的权限。
5. 菜单分组只显示有权限的子页面；组内没有可见页面时隐藏整个分组。
6. 页面相关的全局入口，例如告警铃铛、快捷入口和头像菜单，也必须使用相同权限决定是否显示和是否发起请求。

### 2.4 工作空间和角色

1. 用户只有加入工作空间并绑定角色后，才能在空间列表中看到该空间。
2. 角色权限按工作空间生效，同名权限不能跨工作空间使用。
3. 自定义角色只获得明确勾选的页面权限。
4. 演示账号、初始化角色和角色讲稿引用了新页面时，必须同步更新账号生成命令并刷新现有角色映射。

## 3. 必须完成的自动化验收

每个新增页面至少覆盖以下测试：

| 场景 | 预期结果 |
| --- | --- |
| 权限出现在角色权限树 | 可以在角色配置页勾选 |
| 当前工作空间拥有页面权限 | 查询与操作接口均可调用 |
| 当前工作空间没有页面权限 | 接口返回 HTTP 403 |
| 只在空间 A 拥有权限，请求空间 B | 接口返回 HTTP 403 |
| 直接输入页面 URL 且无权限 | 跳转无权限页，不能进入子页面 |
| 页面无权限 | 顶部菜单、分组及相关全局入口不显示 |
| 用户未加入某个空间 | 空间列表中不显示该空间 |

交付前执行：

```bash
set -e
set -a
source .env.local
set +a
./.venv/bin/python apps/manage.py check
./.venv/bin/python apps/manage.py test <目标权限测试模块> --keepdb --noinput
```

前端在 `ui/` 目录执行目标文件 ESLint、`pnpm run type-check` 和 `pnpm run build`。

## 4. 禁止事项

- 禁止只加路由，不加权限常量和角色权限树。
- 禁止只隐藏前端菜单，不保护后端接口。
- 禁止后端只保护 GET，而让 POST、PUT、DELETE 绕过页面权限。
- 禁止子页面因为没有自己的 `meta.permission` 而绕过父菜单权限。
- 禁止把不带工作空间范围的权限用于工作空间业务接口。
- 禁止给普通内置用户默认开放全部新增业务页面。
- 禁止在没有产品决策的情况下擅自把新增 V1 页面拆成多种操作权限。

## 5. 需求变化时的处理

如果后续明确要求“同一页面内区分只读人员和操作人员”，再进行细粒度升级。升级必须同时完成权限常量、角色配置、前端操作入口、后端每个接口、演示角色、测试和本文档，不允许只修改其中一层。
