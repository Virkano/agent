# 第六阶段：营销客户名单与客户归因测试文档

测试日期：2026-09-01

## 本阶段交付范围

本阶段在“营销任务”基础上补齐客户维度闭环：

1. 新增营销客户名单模型与接口。
2. 营销任务页面增加“客户”入口，可查看、新增、编辑、删除客户。
3. 每个客户生成独立测试链接，链接带 `marketing_task_id` 和 `marketing_customer_id`。
4. 聊天打开后，首条消息入库时保留任务与客户归因字段。
5. 营销任务复盘增加客户漏斗指标：目标客户、待触达、已触达、已咨询、有意向、无意向、转人工。

## 涉及页面

- 管理端：`http://127.0.0.1:3000/admin/marketing-task`

## 本阶段修复的问题

1. 修复普通聊天接口首条消息时覆盖 `open` 阶段缓存 `source` 的问题，否则客户链接带了参数，但真正入库时会丢掉营销任务/客户归因。
2. 修复客户归因方法中提前 `return` 导致客户字段无法写入的问题。
3. 去掉客户手机号/标识的数据库唯一约束，允许运营先创建“手机号未知”的客户，后续再补全信息。
4. 重新启动本地 embedding 服务，避免检索步骤调用 11636 端口失败导致 JSON 解析错误。

## 操作说明

### 新增客户名单

1. 进入“营销任务”。
2. 找到目标任务，点击“客户”。
3. 点击“新增客户”。
4. 填写客户名称、手机号/客户标识、省份、当前套餐、近月流量、近月通话、客户状态和备注。
5. 点击“保存”。

### 客户级对话测试

1. 在客户名单中找到客户。
2. 点击“测试”打开客户专属对话链接。
3. 输入套餐升级相关问题。
4. 返回应围绕套餐、权益、费用透明、转人工边界等内容回答。

### 查看客户漏斗复盘

1. 进入“营销任务”。
2. 点击目标任务的“复盘”。
3. 查看目标客户、已触达/已咨询、有意向/转人工等指标。

## 暂不大规模改造的处理方式

本阶段没有重写原有聊天主流程，而是通过 `Chat.source` 扩展归因字段实现客户级闭环。这样做的好处是：

- 不影响已有智能体、知识库、模型和对话主链路。
- 现有工作空间都可以继续使用营销任务能力。
- 后续如果要做批量触达、外呼、短信、企业微信等渠道，只需要基于客户名单和任务状态继续扩展，不需要推倒当前流程。

下一步建议进入“营销素材/话术模板与任务编排”阶段，把客户名单和智能体回答再往运营动作侧推进。
