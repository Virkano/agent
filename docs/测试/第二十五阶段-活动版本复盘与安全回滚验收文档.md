# 第二十五阶段：活动版本复盘与安全回滚验收文档

## 1. 本阶段交付范围

本阶段补齐营销活动从“配置变更”到“效果复盘”再到“安全恢复”的闭环：

1. 保存活动的每个配置版本，并展示版本号、变更字段、操作人和审批信息。
2. 只允许活动创建人恢复已经审批通过的历史版本。
3. 恢复历史版本时创建一个新的草稿版本，不直接覆盖历史记录，且必须重新提交审批。
4. 活动复盘增加按省份、按当前套餐的效果分层。
5. 复盘结果由后端生成 Excel，前端只负责鉴权下载。
6. 已创建营销任务中的活动快照、已发生的客户对话及归因记录均保持不变。

## 2. 操作步骤

### 2.1 查看活动版本

1. 登录管理端，进入“营销活动库”。
2. 在任一活动的操作列点击“版本”。
3. 查看版本号、变更类型、审批状态、操作人、变更字段和完整活动配置。
4. 展开不同版本，核对权益、费用说明、合约说明、适用省份、套餐关键词和有效期。

预期结果：最新版本排在最前；发生变化的字段有明确标识；基线版本和后续版本均可追溯。

### 2.2 恢复历史版本

1. 选择一个“已通过”且不是当前版本的历史版本。
2. 点击“恢复为新草稿”，确认操作。
3. 返回活动列表，核对活动版本号已增加，活动状态为“已暂停”，审批状态为“未提交”。
4. 由活动创建人重新提交，再由另一位工作空间主管审批。

预期结果：历史版本不被删除或修改；恢复后不能绕过审批直接上线；非活动创建人无恢复权限；未审批版本不能作为恢复源。

### 2.3 查看并导出效果复盘

1. 在活动列表点击“效果”。
2. 核对汇总指标：关联任务数、归因会话数、客户数、意向数、已办理数、转人工数、无意向数、意向率和转人工率。
3. 分别打开“按省份”和“按当前套餐”页签，核对分组数据。
4. 点击“导出复盘 Excel”。
5. 打开下载的 `.xlsx` 文件，检查三个工作表：`复盘汇总`、`省份效果`、`套餐效果`。

预期结果：下载文件不是 CSV；数量列为数值，比例列为 Excel 百分比；工作表支持筛选、冻结表头；数据与页面展示一致。

## 3. 后端接口

- 查看版本：`GET /admin/api/workspace/{workspace_id}/marketing/campaign/{campaign_id}/versions`
- 恢复版本：`POST /admin/api/workspace/{workspace_id}/marketing/campaign/{campaign_id}/versions/{version}/restore`
- 查看复盘：`GET /admin/api/workspace/{workspace_id}/marketing/campaign/{campaign_id}/effect`
- 导出复盘：`GET /admin/api/workspace/{workspace_id}/marketing/campaign/{campaign_id}/effect/export`

Excel 由后端基于当前登录用户可访问的工作空间数据生成。未登录返回 401；活动不存在或不属于当前工作空间返回 404；不会由前端缓存数据拼装文件。

## 5. 异常和边界处理

- 没有命中客户时仍可导出，汇总指标为 0，分层工作表仅保留表头。
- 活动名称等文本以 `= + - @` 开头时按普通文本写入，避免 Excel 公式注入。
- 中文文件名通过标准 `Content-Disposition` 编码返回。
- 导出时间转换为本地时间并移除 Excel 不支持的时区信息。
- 历史任务使用创建任务时的活动快照，恢复活动不会让旧任务或旧对话改变口径。

## 6. 大规模逻辑变更处理原则

对于会影响已有营销任务、对话、审批或归因口径的改动，采用增量演进：

1. 新增版本表和新接口，不原地改写历史业务记录。
2. 对已有活动补一条基线版本，保证旧数据也能进入版本链。
3. 新配置只影响新建任务；旧任务继续读取自己的活动快照。
4. 恢复动作生成新草稿并重新审批，不把数据库回滚等同于业务回滚。
5. 先用自动化测试验证服务层和文件结构，再做真实接口及浏览器验证。
6. 若上线后需要撤回，可暂停新版本活动；已有历史快照与审计记录仍可追踪。

## 7. 建议人工抽测数据

准备至少两个客户：一个广东 199 元套餐有意向客户、一个浙江 299 元套餐已办理客户。打开活动效果后，应看到省份和当前套餐各两条分组；导出的省份工作表中，广东客户数为 1、意向率为 100%，浙江客户数为 1、办理率为 100%。
