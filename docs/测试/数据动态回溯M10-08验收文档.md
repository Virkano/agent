## 2. 数据模型与规则

新增 `RehearsalTracebackSnapshot`，核心规则如下：

- `FULL_INSTANCE`：聚合实例全部可用事实。
- `INCIDENT_WINDOW`：围绕故障与场景事件自动确定回溯窗口。
- `CUSTOM`：必须显式提供开始和结束时间。
- `READY`：窗口内存在事实，可正常回放。
- `EMPTY`：窗口内没有匹配事实，仍保存快照与筛选条件用于审计。
- `ARCHIVED`：预留归档状态；V1 不删除历史回溯。
- 工作空间内按 `request_id` 幂等，重复提交返回原快照。
- 回溯生成时把节点、时间线、差值和转移结果写入 JSON 快照；之后源数据变化不会改写既有回溯结果。
- `checksum` 用于识别快照内容，详情页展示校验摘要。

## 3. 管理接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/admin/api/workspace/{workspace_id}/rehearsal/traceback` | 分页查询回溯快照 |
| POST | `/admin/api/workspace/{workspace_id}/rehearsal/instance/{instance_id}/traceback` | 为实例生成回溯快照 |
| GET | `/admin/api/workspace/{workspace_id}/rehearsal/traceback/{traceback_id}` | 查看节点、差值、转移和不可变时间线 |
| GET | `/admin/api/workspace/{workspace_id}/rehearsal/traceback/export` | 按当前筛选条件导出 CSV |

Dashboard 已同步返回 `traceback_count`、`traceback_ready_count` 和最近回溯列表；预演实例详情已同步返回 `traceback_count` 和关联快照。
