# M11-03 主数据读取审计与敏感日志脱敏验收

日期：2026-09-21。范围：用户与营销客户主数据的直接 GET 接口，以及通用操作日志的新写入事实。

## 交付

- 新增 `master_data_access_event` 追加式读取事件表，记录业务模型、工作空间、操作者 ID、动作、结果、路由模板、范围标识 SHA-256 和查询字段名；不记录查询值、返回内容、联系方式或凭证。模型迁移 `system_manage.0006_master_data_access_audit` 已应用开发库。
- 用户资料、用户列表/成员/分页/单条详情，以及营销客户列表/分页 GET 接口接入读取事件。业务成功、权限拒绝和异常分别有结果状态；审计写入失败时不放行敏感读取结果。
- 通用 `Log` 的新写入改为元数据化：请求只保留路由模板、正文/查询字段名，操作者只保留 ID/角色，操作对象只保留字段名；包括原有自定义详情回调在内，不再把正文或查询值存入通用审计表。
- 资产目录将 `users.User`、`marketing.MarketingCustomer` 的审计状态更新为 `DIRECT_API_PARTIAL`，指向新事件表；最新导出为 184 个模型、893 条 API 路由。

## 验证

- Django `check` 与 `makemigrations --check --dry-run` 通过，目标 Ruff 通过。
- 11 项相关测试通过：审计成功/拒绝与值不落库、通用日志脱敏、真实客户与用户 GET 路由写事件、资产清单，以及客户导入回归。
- 本地 `--noreload` 后端已重启，直连 `/admin/api/user/profile` 返回预期未登录 401，说明新进程的路由可用。
- 资产清单已重导出：[最新清单](../../output/m11-02/asset-inventory.json)。

## 边界

目前只覆盖上述直接 GET 入口；内部服务、跨域查询和对象文件读取未被认定为全面审计。Token 认证阶段就被拒绝的请求尚未进入视图方法，因此不在这张读取事件表中。旧 `Log` 历史记录未自动改写，需在独立评估备份、保留策略和访问控制后治理。本次也未覆盖 ORM DEBUG SQL 日志或其他应用自定义日志。范围哈希不是加密或匿名化保证，审计表仍按受限数据管理。
