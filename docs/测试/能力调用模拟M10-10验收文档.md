# 能力调用模拟 M10-10 验收文档

## 1. 验收范围

对应建设方案 X27“能力调用模拟”。本任务在统一预演实例之上补齐 API Mock 与原子能力沙盒，使预演人员可以在不访问真实生产接口的前提下构造能力调用，核对成功、失败、超时、耗时、请求响应、重放和战情室分组。

粗粒度 V1 边界：沙盒只模拟能力契约和结果，不发起真实外部网络请求，也不使用真实等待制造延迟；配置的模拟耗时写入开始/结束时间和审计事实。模块内不新增通知中心，仍沿用平台右上角的全局通知入口。

## 2. 已交付能力

- 工作空间级版本化能力 Mock，支持 `API` 与 `ATOMIC` 两类能力、请求方法、隔离端点、必填参数 Schema、成功/失败响应模板和默认模拟耗时。
- 默认能力目录包含“资源状态查询 API”和“故障节点隔离原子能力”，可直接用于演示。
- 能力调用绑定预演实例，保存请求幂等键、同能力调用序号、来源、战情室、请求、响应、能力版本快照、HTTP 状态、耗时和错误信息。
- 支持成功、失败和超时三类受控结果；同一请求幂等键重放返回原记录，不重复写调用或事件。
- 重放会新增不可变调用记录并通过 `replay_of` 关联来源记录，原始请求和能力快照不被覆盖。
- 调用状态写入预演实例事件；能力调用同时投影进 X26 统一模拟记录查询。
- 管理端提供能力目录、隔离调用台、战情室统计、调用筛选、调用历史、详情请求/响应对照和三态重放入口。
- 页面采用“能力沙盒 + 战情室台账”的工业控制风格，明确标识“不访问真实生产接口”。

## 3. 数据模型与迁移

迁移：`apps/rehearsal/migrations/0009_alter_rehearsalinstanceevent_event_type_and_more.py`。

- `RehearsalCapabilityMock`：保存版本化能力契约和响应模板，同工作空间下 `code + version` 唯一。
- `RehearsalCapabilityCall`：保存一次不可变调用事实，同工作空间下 `request_id` 唯一，并按实例和能力生成稳定调用序号。
- `RehearsalInstanceEvent` 新增 `CAPABILITY_CALLED` 事件类型。

## 4. 接口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET / POST | `/admin/api/workspace/{workspace_id}/rehearsal/capability-mock` | 查询或创建版本化能力 Mock |
| GET | `/admin/api/workspace/{workspace_id}/rehearsal/capability-call` | 调用历史、筛选、汇总和战情室分组 |
| POST | `/admin/api/workspace/{workspace_id}/rehearsal/instance/{instance_id}/capability-call` | 在指定预演实例中执行隔离调用 |
| GET | `/admin/api/workspace/{workspace_id}/rehearsal/capability-call/{call_id}` | 查看请求、响应和能力快照 |
| POST | `/admin/api/workspace/{workspace_id}/rehearsal/capability-call/{call_id}/replay` | 以成功、失败或超时结果新增重放记录 |
