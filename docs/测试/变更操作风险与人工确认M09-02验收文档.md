# 变更操作风险与人工确认 M09-02 验收文档

## 1. 验收范围

M09-02 对应建设方案 X09 的变更风险控制部分，在 M09-01 IVR 会话与事件基础上完成粗粒度闭环：

- 建立工作空间隔离的变更操作、风险评估版本和人工确认记录。
- 按指令完整性、业务逻辑、一致性、影响客户数、跨系统、回退、紧急程度和客户告知综合计分。
- 关键校验失败可直接判为红灯；红灯阻断执行并进入人工确认，黄灯保留风险提示，绿灯自动放行。
- 每次重新评估生成不可覆盖的版本快照，确认记录绑定对应评估版本、风险分和操作人。
- 确认请求支持幂等重放；同一幂等键不能跨变更操作复用。
- 管理端在 IVR 页面内提供风险总览、新建评估、红黄绿台账、判定依据、评估历史和人工放行/驳回。

## 2. 判定规则

| 因素 | 分值 | 级别说明 |
| --- | ---: | --- |
| 指令或执行步骤不完整 | +20 | 警告 |
| 业务逻辑校验失败 | +45 | 关键风险，直接红灯 |
| 数据或配置一致性失败 | +45 | 关键风险，直接红灯 |
| 影响客户 100～999 | +10 | 关注 |
| 影响客户 1000～9999 | +20 | 警告 |
| 影响客户 10000 及以上 | +35 | 关键风险，直接红灯 |
| 跨系统变更 | +15 | 警告 |
| 回退未就绪 | +15；跨系统时 +30 | 跨系统且无回退为关键风险 |
| 紧急变更 | +20 | 警告 |
| 客户告知未就绪 | +10 | 关注 |

总分上限为 100。存在任一关键风险或总分达到 60 判红灯；无关键风险且总分达到 20 判黄灯；低于 20 判绿灯。关键风险优先于分数阈值，例如一致性失败即使总分为 55 仍判红灯。

## 3. 页面与接口

- 页面：`/admin/ivr-simulator`
- 风险仪表盘：`GET /admin/api/workspace/{workspace_id}/marketing/ivr/change/dashboard`
- 新建变更：`POST /admin/api/workspace/{workspace_id}/marketing/ivr/change/operation`
- 变更详情：`GET /admin/api/workspace/{workspace_id}/marketing/ivr/change/operation/{operation_id}`
- 生成风险评估：`POST /admin/api/workspace/{workspace_id}/marketing/ivr/change/operation/{operation_id}/evaluate`
- 人工确认：`POST /admin/api/workspace/{workspace_id}/marketing/ivr/change/operation/{operation_id}/confirm`

## 7. V1 边界与下一步

- 当前风险权重为可解释的确定性 V1 规则，不等同于生产历史数据训练出的风险预测模型。
- 当前人工确认只完成业务状态和审计记录，不直接调用生产割接平台执行变更。
- M09-03 继续实现事中提醒管控、割接操作告知、周期质量报告、时间下钻与导出，完成 X09 粗粒度 V1；生产 IVR 长连接和真实电话线路继续作为外部联调项。
