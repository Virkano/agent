# 第十五阶段：触达批次审批与合规留痕验收文档

## 本阶段目标

把“生成触达批次”和“实际执行触达”之间增加审批关口，避免未经核验的客群、筛选条件或话术直接进入执行。

## 操作与预期

1. 在“营销任务 → 影响客户名单 → 触达批次”中生成一个新批次。
2. 新批次应显示为“待审批”，操作区显示“审批”，执行按钮不可用。
3. 点击“审批”，填写审批意见并选择“通过”或“驳回”。
4. 审批通过后，列表应显示“已通过”，才可进入“执行”。
5. 审批驳回后，列表应显示“已驳回”，仍不可执行；修改筛选依据后可重新提交审批。
6. 在执行抽屉中，审批未通过时应显示提示，不能将批次改为“执行中”，也不能记录触达结果。

## 留痕字段

每个批次保存并返回：审批状态、审批意见、审批人、审批时间。已存在的历史批次默认标记为“已通过”，避免上线后把历史执行数据误判为未审批。

## 自测记录

- 后端迁移检查：通过。
- 审批接口：待审批批次可审批通过并返回审批状态与审批意见；未审批批次尝试进入执行会被业务校验拦截。
- 前端：待审批、已通过、已驳回状态可见；执行入口会按审批状态禁用。

## 说明

当前阶段记录审批事实，但未引入独立“审批人角色”。如果后续需要“创建人不能审批自己创建的批次”或多级审批，应在权限体系中新增审批角色和审批流配置，再把接口权限收紧。
