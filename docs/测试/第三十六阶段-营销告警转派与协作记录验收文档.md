# 第三十六阶段：营销告警转派与协作记录验收文档

## 1. 本阶段目标

在已有“告警生成—认领—处理—关闭—SLA 升级—负责人绩效”链路上补齐多人协作能力，使主管能够指派未认领告警，当前负责人或主管能够转派告警，并通过评论持续记录排查过程。

本阶段增加独立的负责人处理轮次，避免转派后把所有历史耗时错误归集到最后一位负责人。附件暂不接入，后续在文件存储和权限策略明确后独立建设。

## 2. 已交付能力

- 工作空间管理员可以把未认领告警指派给空间成员。
- 当前负责人或工作空间管理员可以转派未关闭告警；转派原因必填。
- 登录用户可以添加协作评论，评论与状态操作统一进入不可覆盖的操作时间线。
- 指派、转派和评论均记录操作人、时间、前后负责人、说明和操作版本。
- 每次负责人变化都会产生独立处理轮次，保存指派人、负责人、指派时间、本轮首次响应时间和轮次结束原因。
- 负责人转派后全局处理 SLA 不重置，避免通过反复转派规避超时；新负责人获得独立的本轮首次响应时限。
- 负责人绩效按处理轮次归集。发生转派时，前后负责人各自的响应耗时和处理结果不会相互覆盖。

## 3. 权限与状态规则

| 操作 | 权限 | 状态限制 | 必填信息 |
| --- | --- | --- | --- |
| 指派 | 工作空间管理员或系统管理员 | 未关闭且当前无负责人 | 负责人 |
| 转派 | 当前负责人、工作空间管理员或系统管理员 | 未关闭且已有负责人 | 新负责人、转派原因 |
| 评论 | 已登录用户 | 无 | 评论内容 |
| 开始处理 | 当前负责人；未认领时可由操作者直接开始 | 待处理或已认领 | 无 |
| 关闭 | 当前负责人或工作空间管理员 | 未关闭 | 处理结论 |

负责人必须属于当前工作空间，新负责人不能与当前负责人相同。已关闭告警不能再次指派或转派，需先重新打开。

## 4. 数据模型与迁移

新增 `marketing_alert_handling_round`：

- `sequence`：告警内递增的处理轮次；
- `assignee` / `assignee_name`：本轮负责人；
- `assigned_by` / `assigned_by_name`：指派或转派操作人；
- `assigned_at` / `first_responded_at` / `ended_at`：本轮关键时间；
- `response_due_at`：本轮首次响应截止时间；
- `resolution_due_at`：继承告警的全局处理截止时间；
- `end_reason` / `end_note`：转派、关闭或重开等轮次结束信息。

迁移文件：`marketing/migrations/0021_alter_marketingalertactionrecord_action_and_more.py`。

告警操作类型新增：`ASSIGNED`、`TRANSFERRED`、`COMMENTED`。

## 5. 接口

### 5.1 指派、转派和评论

`POST /workspace/{workspace_id}/marketing/alert/{alert_id}/collaborate`

指派示例：

```json
{
  "action": "ASSIGN",
  "assignee_id": "用户 UUID",
  "note": "请一线先排查"
}
```

转派示例：

```json
{
  "action": "TRANSFER",
  "assignee_id": "用户 UUID",
  "note": "需要二线调整模型配置"
}
```

评论示例：

```json
{
  "action": "COMMENT",
  "note": "已定位到上游接口超时，正在联系接口负责人"
}
```

告警详情和列表响应新增：

- `handling_rounds`：负责人处理轮次；
- `capabilities.can_assign`：当前用户能否指派；
- `capabilities.can_transfer`：当前用户能否转派；
- `capabilities.can_comment`：当前用户能否评论。

## 6. 页面操作

1. 进入“运营治理 → 运营监控”。
2. 在告警处理台点击“处理”。
3. 未认领告警会向管理员显示“指派负责人”；选择成员并确认后，告警进入“已认领”。
4. 已有负责人时，当前负责人或管理员会看到“转派负责人”；选择新负责人并填写原因后确认。
5. 新负责人点击“开始处理”，记录本轮首次响应时间。
6. 在“添加协作评论”中记录排查进展。
7. 在“负责人轮次”和“协作与处理记录”中核对负责人变化、时间和说明。

## 9. 当前边界与下一步

- 本阶段不上传附件，也不接入对象存储病毒扫描和下载授权。
