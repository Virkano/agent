# 候选精排 M07-03 验收文档

## 1. 验收范围

M07-03 对应建设方案 X03，在 M07-02 多路融合候选集上完成二阶段精排粗粒度 V1：

- 多路召回自动生成候选池，精排输出 TopN。
- 用七项可解释特征计算精排分，并逐项返回特征值、权重、贡献和原因。
- 精排策略按工作空间版本化，支持草稿预览、发布和旧版本自动归档。
- 每次精排保存输入候选、配置快照、输出结果、关联融合运行和耗时。
- 前端提供精排执行、策略新建/发布、版本列表和运行记录。

## 2. 精排基线

粗粒度 V1 使用可调权重的线性精排基线，默认特征如下：

| 特征 | 默认权重 | 含义 |
| --- | ---: | --- |
| 融合召回分 | 40% | M07-02 六路归一化融合结果 |
| 业务规则适配 | 16% | 地域、套餐和用量准入条件是否全部满足 |
| 地域适配 | 10% | 精确地域、全国活动或不匹配 |
| 套餐适配 | 10% | 套餐关键词匹配程度 |
| 用量门槛 | 8% | 流量与通话门槛满足比例 |
| 召回通道覆盖 | 10% | 命中来源数占当前启用通道数比例 |
| 活动优先级 | 6% | 活动优先级数值转换后的归一分 |

公式：`精排分 = Σ(特征值 × 特征权重) / 特征权重总和`。

该基线不伪装成训练模型，优势是当前版本即可配置、解释、回放和审计；M07-04 将基于显式反馈形成增量样本和新版本。

## 3. 数据模型与接口

- `RecommendationRankingVersion`：版本、名称、状态、特征权重、特征定义、指标和发布时间。
- `RecommendationRankingRun`：客户、融合运行、精排版本、候选数、TopN、配置快照、输入输出和耗时。
- `GET /marketing/recommendation/ranking-dashboard`
- `POST /marketing/recommendation/ranking-version`
- `POST /marketing/recommendation/ranking-version/{id}/publish`
- `POST /marketing/recommendation/ranking-infer`

数据库迁移：`marketing.0029_recommendation_ranking_v1`，已应用到本地 PostgreSQL。

## 7. V1 边界与下一步

- 当前精排为可解释权重基线，尚未用反馈自动拟合权重。
- 当前候选池由实时多路召回生成，精排运行与融合运行一一关联以便回放。
- 下一步 M07-04 / X04：统一曝光、点击、转化和负反馈样本，生成并评估增量模型或策略版本。
