# 第二十六阶段：营销对话自动质检验收文档

## 1. 本次交付范围

本次完成第二十六阶段的第一步：在不改变现有客户回答流程的前提下，为营销智能体的每条回答生成可追溯的自动质检结果。

1. 新产生的营销回答保存后自动质检，质检异常不会阻断原有对话保存。
2. 历史营销回答第一次打开任务复盘时自动补齐质检记录。
3. 质检结果独立保存，记录状态、分数、问题类型、具体原因、修改建议、证据和规则版本。
4. 营销任务复盘增加质检汇总、通过率、主要问题分布，以及逐条回答的质检状态和原因。
5. 本步骤只做旁路发现和复盘，不自动改写客户收到的回答，也不直接拦截模型输出。

## 2. 质检状态和判定范围

### 2.1 状态

- `正常`：未命中已配置的风险规则，默认 100 分。
- `需复核`：回答可能无依据、信息不足或重复，需要运营人员判断，但不是确定性高风险。
- `高风险`：出现答非所问、内部话术暴露、未确认资费、未经配置的确定性承诺、省份不一致或系统错误等问题。

### 2.2 当前规则

| 问题类型 | 例子 | 结果 |
| --- | --- | --- |
| 答非所问 | 客户询问套餐，回答 MySQL、数据库或软件升级步骤 | 高风险 |
| 内部话术暴露 | 回答出现“建议坐席话术”“确认用户诉求”“总结建议”等内部标签 | 高风险 |
| 未确认资费 | 活动、客户上下文和问题均未出现 299 元，回答却直接承诺 299 元方案 | 高风险 |
| 未确认承诺 | 回答“保证成功”“立即生效”“永久优惠”等未配置承诺 | 高风险 |
| 省份不一致 | 广东客户收到浙江政策 | 高风险 |
| 重复回答 | 与上一轮高度相同，或者本轮重复相同段落 | 需复核 |
| 活动权益缺失 | 已命中营销活动，但回答没有体现活动名称或已配置权益 | 需复核 |
| 引用缺失 | 营销问题既未命中活动，又没有知识库引用 | 需复核 |
| 内容过短 | 回答为空或短到无法解决问题 | 需复核 |
| 运行异常 | 回答中出现可识别的运行错误或堆栈内容 | 高风险 |

金额校验允许使用客户问题、当前套餐、客户使用信息及命中活动配置中已经存在的金额，不会把这些已知金额误判成编造资费。

## 3. 页面验收步骤

1. 登录管理端，进入当前工作空间。
2. 打开“营销任务”。
3. 找到“存量客户套餐升级首轮触达任务”，点击“复盘”。
4. 在复盘汇总中核对：
   - `质检结果`显示正常、待复核和高风险数量；
   - `质检通过率`显示正常回答占全部已质检回答的比例；
   - `主要质检问题`显示问题原因和数量。
5. 向下查看“最近对话”表格，核对新增的`质检状态`和`质检原因`两列。
6. 检查下面两条已有记录：
   - 问题“199 的套餐呢”的回答应显示`正常 · 100分`；
   - 问题“我的归属地是广东”的回答因为已命中活动但没有明确活动权益，应显示`需复核 · 80分`，并给出重写建议。

本地真实数据验收结果：35 个会话、61 条回答；正常 21 条、需复核 29 条、高风险 11 条，质检通过率 34.4%。该比例反映现存历史对话质量，不代表规则运行异常。

## 4. 接口验收

接口：

`GET /admin/api/workspace/{workspace_id}/marketing/task/{task_id}/effect/{current_page}/{page_size}`

验收要点：

1. 正常登录并具有当前工作空间访问权限时返回 200。
2. 未登录时返回 401，不返回页面 404 或接口 500。
3. `metrics`中包含：
   - `quality_pass_count`
   - `quality_pending_count`
   - `quality_high_risk_count`
   - `quality_pass_rate`
   - `quality_issue_summary`
4. 每条`records.records`包含`quality_review`，其中有状态、分数、原因、修改建议、证据和规则版本。

## 6. 异常与兼容处理

- 质检采用独立数据表，不修改原有聊天记录、知识库引用、活动快照和转化归因。
- 质检异常会写日志，但不会让聊天记录保存失败，因此不会把旁路能力变成对话接口 500 的新来源。
- 老数据不做一次性全库迁移；只在查看相关任务复盘时按任务补齐，避免启动或发布阶段长时间锁表。
- 每条记录保存规则版本；规则调整后可重新计算，原始客户问题和回答仍保持不变。
- 没有关联智能体或没有对话的任务仍返回完整的零值质检指标，页面可以正常打开。

## 7. 大规模改变现有逻辑时的处理方式

发送前拦截、自动改写回答属于高影响改动，本次没有直接接入主链路。后续按以下顺序推进：

1. 先用当前旁路质检统计真实误报和漏报。
2. 增加人工复核队列，允许确认、驳回和保存修订答案，形成可审计样本。
3. 仅对确定性高风险规则增加工作空间级开关，默认关闭并灰度启用。
4. 开启拦截时保留原回答、拦截原因和人工处理结果，不覆盖历史证据。
5. 设置快速关闭开关；出现误报时可以只关闭发送前拦截，不影响聊天、任务复盘和历史质检数据。
