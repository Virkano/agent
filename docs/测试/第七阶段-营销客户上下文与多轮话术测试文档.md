# 第七阶段：营销客户上下文与多轮话术测试文档

## 1. 本次修复目标

解决营销智能体对话中出现的两类问题：

- 用户问“套餐升级问题”时，不能跑偏成 MySQL、数据库、软件或系统升级。
- 用户继续追问“那贵不贵？”时，不能泛泛回答或重复分析框架，必须结合营销任务、客户画像和费用透明边界给出可用话术。

## 2. 涉及能力

- 营销任务打开对话时，将任务、场景、目标客群、客户画像写入对话来源。
- 对话生成链路读取营销来源，注入客户上下文。
- 费用类问题增加轻量兜底增强，避免本地小模型输出过泛。
- 已发布应用版本同步更新营销助手提示词，并关闭问题改写，避免多轮追问被改写成孤立问题。

## 3. 页面验证路径

1. 打开后台：`http://localhost:3000/admin/marketing-task`
2. 进入工作空间：`营销闭环测试工作空间`
3. 找到任务：`存量客户套餐升级首轮触达任务`
4. 点击“影响客户名单”
5. 使用第一条客户测试：
   - 客户：张女士
   - 省份：广东
   - 当前套餐：199元套餐
   - 近月流量：80GB
   - 近月通话：300分钟
6. 点击该客户的“打开对话”

## 4. 推荐测试问题

### 用例 1：套餐升级费用问题

输入：

```text
我流量经常不够，升级会不会有额外费用？
```

期望：

- 接口无 404、无 500。
- 回答必须是通信套餐升级，不得出现 MySQL、数据库、软件升级、系统升级。
- 回答应包含客户画像，例如张女士、广东、199元套餐、80GB。
- 回答应提示核实月费差额、优惠期限、合约期、到期恢复价、退订影响等费用透明事项。
- 不得编造具体优惠金额。

### 用例 2：多轮追问“贵不贵”

继续输入：

```text
那贵不贵？
```

期望：

- 接口无 404、无 500。
- 回答应承接上一轮客户上下文。
- 回答不能只说“具体取决于当地活动”。
- 回答应给出可执行话术，例如优先核实同价扩容或小幅升档活动，费用、优惠期限和合约期确认清楚后再由客户决定是否办理。
- 如客户追问具体多少钱、要求马上办理或对费用/合约有异议，应提示转人工或本地受理确认。

## 6. 注意事项

当前本地使用的是较小的 Ollama 模型，纯模型生成容易出现表达空泛或复读模板。因此本阶段增加了“营销费用类回答增强”：

- 只对带有 `marketing_task_id` 和 `marketing_customer_id` 的营销任务对话生效。
- 普通智能体、普通知识库问答不受影响。
- 具体优惠金额、可办理资格仍以知识库配置或本地人工核实为准，系统不会自动编造。
