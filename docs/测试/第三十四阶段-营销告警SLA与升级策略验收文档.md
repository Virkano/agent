# 第三十四阶段：营销告警 SLA 与升级策略验收文档

## 1. 本阶段目标

在已有“告警自动扫描—站内通知—人工处理”链路上增加可配置的服务时限，让系统能够识别“多久没人接”和“多久还没处理完”，并将超时告警只升级通知一次。

本阶段没有改写营销对话、营销任务、质检和触达执行的主流程；SLA 扫描失败也不会阻断这些核心流程。

## 2. 用户能看到的变化

- “告警规则”升级为“告警规则与 SLA”，每条规则可设置首次响应分钟数、处理完成分钟数和升级接收人。
- 告警列表新增“SLA”列，显示待响应、响应超时、处理中、处理超时或已完成。
- 新增“SLA 超时”快速筛选和超时数量。
- 告警处理抽屉显示首次响应时限、处理完成时限、剩余或超时时长、升级接收人。
- “认领”、“开始处理”或“关闭告警”均会记录首次响应时间。
- 告警重新打开时重新起算 SLA，不沿用上一轮的超时状态。
- 首次响应或处理完成超时后，站内通知可直达对应告警处理抽屉。

## 3. SLA 判定规则

```text
告警创建或重新打开
        ↓
记录 SLA 起算时间，生成响应截止和处理截止时间
        ↓
未记录首次响应且超过响应截止时间
        → 写入“首次响应超时”处理记录并通知
        ↓
告警未关闭且超过处理截止时间
        → 写入“告警处理超时”处理记录并通知
```

去重和并发约束：

- 每个告警每个 SLA 阶段只记录一次升级时间，定时扫描不会每 5 分钟重复通知。
- 扫描时锁定告警主记录，规则单独批量读取，避免 PostgreSQL 对可空外连接执行 `FOR UPDATE` 失败。
- 配置的处理完成时限不得小于首次响应时限。
- 升级接收人必须是当前工作空间的有效成员，防止跨工作空间配置和数据泄漏。

## 4. 通知对象

- 规则已配置升级接收人时，SLA 超时通知只发给该人。
- 规则未配置升级接收人时，回退到现有的工作空间成员通知机制。
- 普通的“新告警”和“告警重新打开”通知范围保持不变。

## 6. 手工验收步骤

### 6.1 配置 SLA

1. 登录管理端，切换到需要验收的工作空间。
2. 进入“运营监控”，点击“告警规则”。
3. 选择一条规则，设置首次响应和处理完成分钟数。
4. 在“升级接收人”中选择一位当前工作空间成员，点击“保存规则”。
5. 确认页面显示“告警规则已保存”。

### 6.2 验证首次响应

1. 准备一条达到规则阈值的异常，点击“同步告警”或等待后台扫描。
2. 超过首次响应时限后再次扫描。
3. 勾选“SLA 超时”，确认告警显示“响应超时”。
4. 打开“处理”，确认处理记录中只有一条“首次响应超时”。
5. 点击“认领”或“开始处理”，确认首次响应时间被记录，后续不再生成响应超时。

### 6.3 验证处理完成超时

1. 保持告警处于待处理、已认领或处理中，不关闭告警。
2. 超过处理完成时限后触发扫描。
3. 确认告警显示“处理超时”，处理记录中出现一条“告警处理超时”。
4. 重复扫描，确认处理记录和通知不重复新增。

### 6.4 验证通知直达

1. 使用配置的升级接收人账号登录。
2. 点击页面右上角“营销告警通知”。
3. 确认出现“首次响应超时”或“告警处理超时”通知。
4. 点击通知，确认直接打开对应告警，并将该通知标记为已读。

## 9. 不宜在本阶段硬改的部分

以下能力会明显扩大外部系统依赖或改变现有组织流程，本阶段保留为待开发：

- 企业微信、钉钉、短信和邮件等外部通知渠道与发送回执。
- 多级升级链、值班表、静默时段和节假日时钟。
- 按告警级别重复提醒和通知频率控制。

这些功能建议以“可插拔通知通道 + 独立排班规则 + 发送任务表”逐步增加，不直接修改对话或营销任务主逻辑。
