# M11-02 数据资产目录与接口清单验收

日期：2026-09-21。范围：M11 元数据盘点，不读取业务记录。

## 交付与运行

在仓库根目录加载 `.env.local` 后执行：

```bash
set -e
set -a
source .env.local
set +a
./.venv/bin/python apps/manage.py export_asset_inventory
./.venv/bin/python apps/manage.py export_asset_inventory --output output/m11-02/asset-inventory.json
```

命令从 Django 已注册模型与实际 URL 树生成确定性的 JSON 清单，并输出 SHA-256；不连接业务表读取行数据。模型记录数据表、业务域、岗位负责人、初始分级、敏感字段名提示、拟入湖数据集及接入状态；接口记录管理/对话入口、路由、方法、视图来源、分层、OpenAPI/DCOOS/EOP 待核验状态。未知归属或关键主数据模型缺失时命令失败。

## 验收结果

- M11-02 当时盘点 183 个业务模型、893 条 API 路由；其中管理入口 859 条、对话入口 34 条。M11-03 新增读取审计模型后，链接中的最新导出为 184 个模型、893 条路由。
- 模型初分级：L2 内部 3、L3 敏感 159、L4 受限 21；92 个模型有名称提示的敏感字段。此为保守初筛，不是逐字段合规确认。
- 接口分层：业务服务 577、渠道 26、编排 81、平台 209。2 条路由的方法无法从视图声明可靠解析，保留 `UNRESOLVED`，不猜测 HTTP 方法。
- `users.User` 和 `marketing.MarketingCustomer` 列为主数据；M11-02 验收时读取审计均为 `GAP`。M11-03 后直接读取接口已接入事件，最新导出改标 `DIRECT_API_PARTIAL`，其他内部读取仍待核验。所有拟入湖目标均为 `PROPOSED_NOT_CONNECTED`；EOP 注册、DCOOS 兼容及 OpenAPI 完整性均未标为已通过。
- 4 项自动化测试、目标 Ruff 和真实导出通过。导出文件：[资产清单](../../output/m11-02/asset-inventory.json)。

## 边界与下一步

负责人目前是岗位角色而非实名；对象文件、JSON 内部内容、真实访问权限及审计覆盖仍需逐项核验。此清单不能证明数据已入湖、接口已注册 EOP 或符合 DCOOS。下一步优先补主数据读取审计与敏感请求日志脱敏，再继续安全扫描、备份恢复和性能基线。
