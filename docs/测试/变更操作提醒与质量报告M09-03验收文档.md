# 变更操作提醒与质量报告 M09-03 验收文档

## 1. 验收范围

M09-03 对应建设方案 X09 的事中管控与质量报告部分，在 M09-01 会话事件和 M09-02 风险确认基础上完成粗粒度闭环：

- 建立变更前、执行中、变更后的提醒/割接告知记录，支持操作人员与客户两类接收对象及站内、IVR、短信、人工四类通道留痕。
- 通信事件使用工作空间级请求编号保证幂等，状态按待发送、已发送、已确认、失败流转；同一幂等键不可跨变更操作复用。
- 站内通信进入右上角全局通知铃铛，不再建设模块内通知中心。
- 开始执行前必须存在一条已发送或已确认的“变更前”通信；完成变更前必须存在一条已发送或已确认的“执行中”通信。
- 开始、完成和终止操作形成不可覆盖的修订轨迹，保留前后状态、操作人、时间和说明。
- 生成周期质量报告快照，支持日期趋势、单日下钻以及 UTF-8 BOM CSV、嵌入 CJK 字体的 PDF 导出。
- 管理端在 `/admin/ivr-simulator` 内集中展示执行台账、提醒告知、操作轨迹、周期报告和日期下钻。

## 2. 状态与门禁

### 2.1 通信状态

| 当前状态 | 允许转移 | 说明 |
| --- | --- | --- |
| 待发送 | 已发送、失败 | 创建后不直接视为已触达 |
| 已发送 | 已确认、失败 | 站内发送时同步写入全局铃铛 |
| 失败 | 已发送 | 允许修复后重试 |
| 已确认 | 无 | 终态，不允许倒退 |

重复提交相同目标状态返回原结果，不重复写通知。跨顺序转移会被拒绝。

### 2.2 执行门禁

| 操作 | 前置条件 | 结果 |
| --- | --- | --- |
| 开始执行 | 风险已评估、未驳回、红灯已人工放行，且至少一条变更前通信已发送/确认 | 未开始 → 执行中 |
| 完成变更 | 当前为执行中，且至少一条执行中通信已发送/确认 | 执行中 → 已完成 |
| 终止变更 | 当前为未开始或执行中 | → 已终止 |

PostgreSQL 加锁只锁通信或变更主表，不在同一 `select_for_update()` 查询中携带可空用户、IVR 会话等外连接。

## 3. 页面与接口

- 页面：`/admin/ivr-simulator`
- 管控仪表盘：`GET /admin/api/workspace/{workspace_id}/marketing/ivr/change/control/dashboard`
- 变更管控详情：`GET /admin/api/workspace/{workspace_id}/marketing/ivr/change/control/operation/{operation_id}`
- 新建提醒/告知：`POST /admin/api/workspace/{workspace_id}/marketing/ivr/change/operation/{operation_id}/communication`
- 更新通信状态：`POST /admin/api/workspace/{workspace_id}/marketing/ivr/change/communication/{communication_id}/status`
- 开始/完成/终止：`POST /admin/api/workspace/{workspace_id}/marketing/ivr/change/operation/{operation_id}/control`
- 生成质量报告：`POST /admin/api/workspace/{workspace_id}/marketing/ivr/change/quality/report`
- 报告详情：`GET /admin/api/workspace/{workspace_id}/marketing/ivr/change/quality/report/{report_id}`
- 日期下钻：`GET /admin/api/workspace/{workspace_id}/marketing/ivr/change/quality/report/{report_id}/drilldown?date=YYYY-MM-DD`
- 导出：`GET /admin/api/workspace/{workspace_id}/marketing/ivr/change/quality/report/{report_id}/export/{csv|pdf}`

迁移 `marketing.0033_change_operation_control_report_v1` 已应用到本地 Docker PostgreSQL。重启 `--noreload` 后端后，直连 8080 和 Vite 代理 3000 的新增受保护接口均返回预期的 401，不是 404；管理页面返回 200。
