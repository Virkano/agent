P0-06 / M10-05 已完成，建设方案功能对比表 X22“告警模拟”形成可运行、可演示、可追溯的粗粒度 V1。

本步复用 M10-01～M10-04 的预演实例、趋势批次、场景执行和人工闭环，新增：

- 告警“待上报 → 活动告警 → 已确认 → 已恢复”状态链路。

- 告警事件与申告、指标、处置、场景事件合并到统一预演时间轴。
- 前端告警面板、配置抽屉、详情控制抽屉和时间轴筛选。

## 2. 数据模型与状态规则

新增 `RehearsalAlertTemplate`、`RehearsalAlert` 和 `RehearsalAlertEvent`。

默认模板 `NETWORK-ALERT-V1` 包含网络时延和丢包率两类规则。创建告警时会固化模板、规则、指标、阈值、网元和上下文快照，避免后续模板调整影响历史审计。

状态规则：

- 新建告警默认进入“待上报”。
- 只有待上报告警可以上报为“活动告警”。
- 只有活动告警可以确认。
- 活动或已确认告警可以恢复。
- 告警操作时间不能早于告警发生时间或上一条事件时间。
- 幂等请求编号在同一工作空间唯一，重复请求返回已有告警，跨实例复用会被拒绝。

## 3. 管理接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `/admin/api/workspace/{workspace_id}/rehearsal/alert-template` | 查询或新建告警模板版本 |
| GET | `/admin/api/workspace/{workspace_id}/rehearsal/alert` | 筛选模拟告警 |
| POST | `/admin/api/workspace/{workspace_id}/rehearsal/instance/{instance_id}/alert` | 在预演实例下配置模拟告警 |
| GET | `/admin/api/workspace/{workspace_id}/rehearsal/alert/{alert_id}` | 查看告警详情、事件、关联场景和趋势 |
| POST | `/admin/api/workspace/{workspace_id}/rehearsal/alert/{alert_id}/operate` | 上报、确认或恢复告警 |
| GET | `/admin/api/workspace/{workspace_id}/rehearsal/instance/{instance_id}/timeline` | 查询统一预演时间轴 |
