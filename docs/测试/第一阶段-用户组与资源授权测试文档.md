# 第一阶段：用户组与应用/知识库资源授权测试文档

## 1. 测试范围

本次覆盖：

- 系统/工作空间用户组管理接口的后端权限门禁。
- 对话用户创建、编辑、删除、密码和用户组成员管理接口。
- 应用/知识库按用户组授权和按用户授权接口。
- 用户没有用户组时不得通过旧授权记录获得资源访问权限。
- 授权数据按资源所属工作空间隔离。
- 不存在的用户组、用户和不支持的资源类型返回明确错误，不产生 500。
- 内置用户组 `default`、`dingtalk` 不允许删除。
- 授权变更后的用户权限缓存清理。
- 既有前端路由和前端生产构建不受影响。

## 4. API/权限验收用例

以下请求的前缀按配置为 `/admin/api`；工作空间接口使用实际工作空间 ID 替换 `<workspace_id>`。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| AUTH-01 | 普通用户 GET `/admin/api/system/group` | 403，不返回用户组数据。 |
| AUTH-02 | 管理员 GET `/admin/api/system/group` | 200，返回用户组列表。 |
| AUTH-03 | 工作空间管理员 GET `/admin/api/workspace/group` | 200，仅在其工作空间权限有效。 |
| AUTH-04 | 普通用户 POST 用户组成员接口 | 403。 |
| AUTH-05 | 管理员删除 `default` 或 `dingtalk` 用户组 | 400，内置组仍存在。 |
| AUTH-06 | 授权接口传入不存在的用户组 | 400，不写入授权记录。 |
| AUTH-07 | 用户授权接口传入不存在的对话用户 | 400，不写入授权记录。 |
| AUTH-08 | 授权接口传入 `TOOL`/`MODEL` 作为对话资源类型 | 400。 |
| AUTH-09 | 用户只有旧用户组个人授权记录但当前不在该用户组 | 不得通过授权校验。 |
| AUTH-10 | A 工作空间资源带 B 工作空间授权记录 | 不得通过授权校验。 |
| AUTH-11 | 同一用户撤销用户组授权后再次访问 | 重新查询权限，不继续使用旧缓存。 |
| ROUTE-01 | `/admin/system/user`、`/system/chat-user`、`/system/group` 页面 | 前端路由可打开，不出现 404。 |
| ROUTE-02 | `/system/resource-management/application`、`knowledge` 页面 | 前端路由可打开，授权抽屉接口不出现 500。 |
| ROUTE-03 | `/locales/index.json`、`/admin/locales/index.json` | 200，返回 JSON；无外置语言包时返回 `{"locales":[]}`。 |
| ROUTE-04 | `/admin/api/user/profile` 无 token/错误 token | 401 JSON，不返回 500。 |

## 5. 操作验收

1. 管理员进入“系统管理 → 对话用户”，创建测试对话用户。
2. 进入“用户组”，创建 `test-sales` 用户组。
3. 将测试对话用户加入 `test-sales`。
4. 在应用资源授权中给 `test-sales` 授权一个测试应用。
5. 使用对话用户登录访问该应用，确认可以访问。
6. 撤销 `test-sales` 的应用授权，重新建立会话，确认访问被拒绝。
7. 给该用户增加个人拒绝记录，确认即使用户组授权仍存在，也按拒绝规则处理。
8. 删除测试用户组前，确认内置组删除操作被阻止；测试组删除后，成员关系和授权记录按外键级联清理。

## 6. 失败定位

| 现象 | 优先检查 |
| --- | --- |
| 页面 404 | `ui/src/router/modules/system.ts`、`ui/src/router/routes.ts`、构建产物是否更新。 |
| 接口 403 | Bearer token、角色映射、工作空间 ID 和请求路径别名。 |
| 接口 400 | 请求 body 是否为数组、用户组/用户 ID 是否真实存在、资源类型是否为 APPLICATION/KNOWLEDGE。 |
| 权限撤销后仍可访问 | `ResourceChatUser*Authorize` 记录、用户组关系、权限缓存清理和新会话 token。 |
| 接口 500 | 查看应用日志中的 traceback；重点检查 UUID、外键、数据库迁移和请求 body 类型。 |

## 7. 回归判定

- 自动检查全部通过。
- AUTH-01～AUTH-11 全部符合预期。
- ROUTE-01～ROUTE-02 页面和接口无 404/500。
- 任何新增 500、越权访问或授权撤销不生效，均判定不通过。
