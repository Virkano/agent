# 第三十八阶段：全局告警铃铛收口验收文档

## 1. 目标与边界

营销告警继续使用后台右上角的全局通知铃铛，不建设企业微信、钉钉、短信、邮件或 Webhook 等外部通知渠道，也不新增独立的通知页面。

通知仍按工作空间和当前登录用户隔离；“全局”指后台各业务页面共用同一个顶部通知入口，而不是向所有用户无差别广播。

## 2. 已实现能力

- `MarketingNotificationCenter` 保持挂载在全局 `UserHeader`，主布局和简单布局均可见。
- 铃铛标题统一为“全局通知”，当前分类显示为“营销告警”。
- 未读数继续显示在右上角铃铛徽标，最大显示 99。
- 支持“全部 / 未读”切换。
- 支持按紧急、关注、提示三级筛选。
- 支持手动刷新；后台页面仍每 60 秒刷新未读数。
- 通知展示事件类型标签，包括新告警、重新打开、SLA 超时、指派、转派、评论、关闭、关注和附件。
- 点击未读通知后自动标记已读，并跳转到对应告警抽屉。
- “全部已读”和进入告警处理台行为保持不变。

## 3. 接口调整

通知分页接口新增可选筛选参数：

- `status`: `UNREAD` 或 `READ`
- `severity`: `CRITICAL`、`WARNING` 或 `INFO`
- `action`: 告警事件类型

通知记录新增返回字段：

- `alert_type`: 告警类型
- `action`: 触发通知的告警事件

本阶段没有数据库结构变更。

## 4. 自动化验收

- 告警模块聚焦测试：22 项通过。
- 新增覆盖：通知按状态、级别和事件筛选，并返回 `alert_type`、`action` 元数据。
- Ruff：通过。
- 前端 ESLint：通过。
- Vue TypeScript 类型检查：通过。

## 5. 手工验收步骤

1. 登录后台后在任意业务页面查看右上角铃铛。
2. 打开铃铛，确认标题为“全局通知”，分类为“营销告警”。
3. 切换“全部 / 未读”，确认列表与未读数一致。
4. 分别选择紧急、关注、提示级别，确认列表正确过滤。
5. 点击刷新按钮，确认列表和未读数更新。
6. 点击一条未读通知，确认通知变为已读并打开对应告警抽屉。
7. 确认通知卡片显示正确的事件标签。

## 6. 后续约束

后续阶段不再规划外部通知通道。新增业务通知时优先复用右上角全局铃铛的数据模型和交互入口，通过通知分类扩展，不重复建设入口。
