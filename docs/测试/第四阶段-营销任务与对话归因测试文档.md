# 第四阶段：营销任务与对话归因测试文档

## 1. 本阶段完成内容

本阶段在“营销场景”之上补齐“营销任务”闭环，目标是让一次营销触达可以被独立配置、独立打开测试链接，并在客户对话落库时记录任务来源，便于后续按任务统计会话数和复盘转化效果。

已完成能力：

- 新增营销任务后端模型 `marketing_task`。
- 新增营销任务管理 API：
  - `GET /admin/api/workspace/{workspace_id}/marketing/task`
  - `GET /admin/api/workspace/{workspace_id}/marketing/task/{current_page}/{page_size}`
  - `POST /admin/api/workspace/{workspace_id}/marketing/task`
  - `PUT /admin/api/workspace/{workspace_id}/marketing/task/{task_id}`
  - `DELETE /admin/api/workspace/{workspace_id}/marketing/task/{task_id}`
- 新增后台菜单页面：`/admin/marketing-task`。
- 营销任务支持关联：
  - 营销场景
  - 智能体
  - 知识库
  - 目标客群
  - 任务目标
  - 触达渠道
  - 目标触达数
- 营销任务列表支持：
  - 按场景筛选
  - 按状态筛选
  - 关键词搜索
  - 打开测试聊天
  - 复制测试链接
  - 查看会话数
- 聊天链接支持携带 `marketing_task_id`：
  - `/admin/chat/{access_token}?marketing_task_id={task_id}`
- 客户从任务链接进入并发送消息后，`application_chat.source` 会记录：
  - `type`
  - `marketing_channel`
  - `marketing_task_id`
  - `marketing_task_name`
  - `marketing_scenario_id`
  - `marketing_scenario_name`

## 5. 手工验收步骤

### 5.1 验收营销任务页面

1. 登录后台。
2. 切换到工作空间“营销闭环测试-存量客户运营空间”。
3. 打开 `/admin/marketing-task`。
4. 检查列表中是否存在“存量客户套餐升级首轮触达任务”。
5. 使用状态筛选“进行中”，确认任务仍能查到。
6. 使用关键词搜索“套餐升级”，确认任务仍能查到。

### 5.2 验收创建任务

1. 点击“创建任务”。
2. 选择“存量客户套餐升级营销场景”。
3. 检查目标客群、任务目标、渠道、智能体、知识库是否自动继承场景配置。
4. 填写任务名称。
5. 保存。
6. 确认列表新增一条任务。

### 5.3 验收任务测试链接

1. 在任务列表点击“测试”。
2. 进入聊天页面。
3. 输入：“我现在是199套餐，想升级套餐，有什么注意事项？”
4. 检查回答是否围绕套餐升级、权益透明、合规提醒、转人工条件展开。
5. 回答中不应出现数据库升级、MySQL、软件升级等无关内容。

### 5.4 验收归因落库

发送消息后，检查数据库 `application_chat.source` 是否包含当前任务信息。

参考查询：

```sql
select id, source
from application_chat
where source ->> 'marketing_task_id' = '{task_id}'
order by create_time desc
limit 5;
```

## 6. 本阶段没有大规模改动的地方

为了不破坏现有聊天、智能体、知识库主流程，本阶段采用“增量外挂”方式：

- 不改现有 Application 主模型。
- 不改现有 Knowledge 主模型。
- 不改变普通聊天入口。
- 不改变原有对话生成逻辑。
- 只在 URL 携带合法 `marketing_task_id` 时补充 source 归因。
- 非法或不匹配的任务 ID 会被忽略，不让客户侧聊天报 500。

后续如果要做“批量触达、客户名单、转化漏斗、任务看板”，建议继续沿着营销任务扩展，不要直接侵入应用和知识库核心表。
