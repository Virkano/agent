## 2. 交付范围

### 2.1 标准事件

- 支持 `WEBHOOK`、`SCHEDULED`、`USER`、`SYSTEM` 四类来源。
- 保存事件 ID、幂等键、类型、主题、发生时间、载荷和元数据快照。
- 事件 ID 与幂等键均按工作空间唯一，重复请求返回原事件和原运行实例。
- 先按已发布流程的事件类型、允许来源匹配，再校验事件契约的必填字段；校验失败时事件不落库。

### 2.2 版本化流程与 DAG

- 同一流程编号自动递增版本号，发布新版本时归档旧发布版本。
- 每个版本固化事件契约、允许来源和节点定义快照，历史运行不受后续版本影响。
- 节点支持数据查询、智能体、报告、通知、工具和人工六类。
- 创建时校验节点编号唯一、依赖存在、禁止自依赖及循环依赖。
- 依赖全部成功后才释放下游；同一层无相互依赖的节点可并行运行。

### 2.3 执行与资源门禁

- 非人工节点复用 M06-01 资源协调服务，自动生成独立调度任务。
- 节点继承资源池、优先级、申请配额和互斥键；资源不足时进入 `WAITING_RESOURCE`。
- 调度任务获得租约后，通过显式“同步推进”把节点切换为 `RUNNING`。
- 人工节点进入 `WAITING_MANUAL`，只接受通过或拒绝。
- 运行、节点、调度关联和人工操作均形成顺序化追加事件。

### 2.4 前端

- 新增“运营分析 → 事件任务编排”导航入口。
- 页面提供流程版本库、运行实例表、关键统计、执行契约说明。
- 支持创建预置五节点流程版本、发布草稿、注入标准事件、查看 DAG、同步推进及节点完成/失败/通过/拒绝。
- 主页面、流程创建抽屉和运行详情抽屉均具备独立滚动能力。

## 3. 核心数据模型

| 模型 | 作用 |
| --- | --- |
| `EventFlowVersion` | 保存不可变流程版本、事件契约和 DAG 节点快照 |
| `StandardEvent` | 保存标准事件与幂等事实 |
| `EventFlowRun` | 保存一次事件与流程版本绑定的运行实例 |
| `EventFlowNodeRun` | 保存节点依赖、资源绑定、输入输出和状态 |
| `EventFlowRunEvent` | 保存运行与节点的顺序化追加事件 |

## 4. API 清单

接口统一前缀：`/admin/api/workspace/{workspace_id}/event-orchestration`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/dashboard` | 汇总流程、事件、运行和等待状态 |
| GET / POST | `/flow` | 查询或创建流程版本 |
| GET | `/flow/{flow_id}` | 查询流程版本详情 |
| POST | `/flow/{flow_id}/publish` | 发布流程版本 |
| POST | `/event` | 接收标准事件并创建匹配运行 |
| GET | `/run` | 查询运行实例 |
| GET | `/run/{run_id}` | 查询 DAG 节点和运行事件 |
| POST | `/run/{run_id}/advance` | 同步资源状态并推进 DAG |
| POST | `/run/{run_id}/node/{node_id}/operate` | 完成、失败、通过或拒绝节点 |

## 8. V1 边界与下一步

本版已实现真实数据库状态机、资源租约门禁和完整事实链，但执行节点由回调按钮收口，不宣称已经连接真实异步执行器。M06-03 将在当前模型上增加条件表达式、节点超时、有限重试、降级与备用路径、自愈动作、关联 Trace ID 和失败链路重放。
