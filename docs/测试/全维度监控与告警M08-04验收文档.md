# 全维度监控与告警 M08-04 验收文档

## 1. 验收范围

M08-04 对应建设方案 X35，完成粗粒度 V1：

- 统一采集模型性能、数据质量、知识时效和系统资源四个维度。
- 监控规则支持关注/紧急双阈值、启停、比较方式、冷却时间和自动响应策略。
- 异常生成可去重、可确认、可恢复的监控告警。
- 重试和回滚均先生成可追溯响应任务；重试任务可人工确认执行，回滚任务等待选择安全版本，避免监控采集直接执行破坏性回滚。
- 平台告警复用既有通用通知字段，统一进入右上角全局告警铃铛，不建设模块内通知中心。
- APScheduler 每 5 分钟采集已有监控规则或业务数据的工作空间。

## 2. 指标清单

| 维度 | 指标 |
| --- | --- |
| 模型性能 | 训练流水线成功率、训练失败数、模型评估通过率、已发布模型版本数 |
| 数据质量 | ETL 成功率、ETL 失败数、ETL 平均质量分、索引向量覆盖率 |
| 知识时效 | 有效文档数、最长未更新时间、最近检索评估命中率、已发布索引版本数 |
| 系统资源 | 后端、PostgreSQL、Redis、Ollama、本地向量服务可用性 |

本地向量服务使用端口连通性作为轻量周期探针；根路径 404 不会被误判为离线。模型实际向量调用仍按项目排障手册执行。

## 3. 接口与页面

- 页面：`/admin/platform-monitoring`
- 仪表盘：`GET /admin/api/workspace/{workspace_id}/platform-monitoring/dashboard`
- 立即采集：`POST /admin/api/workspace/{workspace_id}/platform-monitoring/collect`
- 规则查询/新增/修改：`/platform-monitoring/rule`
- 告警查询与确认/恢复/重试响应：`/platform-monitoring/alert`

页面根容器显式使用 `height: 100%` 和 `overflow-y: auto`，适配父布局的 `overflow: hidden`。

## 6. V1 边界

- 当前是业务数据库聚合与轻量服务探针，Prometheus/OpenTelemetry、日志/链路追踪和生产级时序存储留到架构优化阶段。
- 动态基线、值班表、派单和八类主题指标属于 M03；本模块只提供 X35 所需规则、告警和响应任务底座。
- 外部 MLflow 仍为待外部环境联调项，本地实验、模型注册和流水线闭环不受影响。
- 冷却时间已进入数据契约；V1 通过同一规则告警去重避免重复通知，高级抑制、聚合和静默窗口后续优化。
