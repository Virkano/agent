# 第二十七阶段：人工质检与修订闭环验收文档

## 1. 本阶段交付范围

本阶段把自动质检结果变成可执行的人工处理闭环：

1. 工作空间菜单新增“对话质检”页面。
2. 默认集中展示自动质检为“需复核”或“高风险”且人工状态为“待处理”的回答。
3. 支持按营销任务、自动质检状态、人工处理状态、问题类型和关键词筛选。
4. 支持“确认正常”“确认问题”“提交修订”三种处理动作。
5. 保存复核人、复核时间、复核意见、当前修订答案和人工操作版本。
6. 每次处理新增一条独立历史记录，原回答和既有历史不会被覆盖。
7. 营销任务复盘增加待处理、已复核和已修订数量。

修订答案当前用于人工审核和后续规则优化，不会自动替换已经发送给客户的历史回答，也不会直接进入新的客户对话。

## 2. 操作步骤

### 2.1 打开待处理队列

1. 登录管理端并进入目标工作空间。
2. 点击左侧菜单“对话质检”。
3. 默认筛选条件为“人工状态：待处理”。
4. 优先检查顶部“高风险”数量，再使用任务、问题类型或关键词缩小范围。

预期结果：页面正常打开，不出现路由 404；队列优先显示高风险回答，表格包含任务、客户、客户问题、原回答、自动风险、人工状态和操作入口。

### 2.2 确认正常

适用于规则误报，但人工确认回答可以面向客户展示的情况。

1. 点击目标记录的“处理”。
2. 选择“确认正常”。
3. 可填写判断依据，点击“保存处理结果”。

预期结果：记录状态变为“确认正常”，从默认待处理队列移除；自动质检状态和原回答保持不变。

### 2.3 确认问题

适用于确认回答有问题，但暂时没有可用修订答案的情况。

1. 选择“确认问题”。
2. 必须填写复核意见。
3. 保存处理结果。

预期结果：缺少复核意见时前后端均拒绝提交；成功后保存复核人、时间和问题说明。

### 2.4 提交修订

适用于已经能够给出合规客户回答的情况。

1. 选择“提交修订”。
2. 在“面向客户的修订答案”中填写完整回答。
3. 填写修订原因并保存。
4. 点击顶部“已修订”，重新打开该记录。

预期结果：

- 修订答案不能为空，也不能与原回答完全相同。
- 已修订记录默认展开修订答案。
- “处理历史”显示操作版本、处理人、处理时间、意见和该版本修订答案。
- 原回答仍显示在“原回答（只读证据）”区域，数据库中的聊天记录内容不变。

## 3. 当前真实数据验收

验收工作空间：`营销闭环测试-存量客户运营空间`。

本轮使用一条已存在的高风险回答完成真实修订：

- 客户问题：`我流量经常不够，升级会不会有额外费用？`
- 原回答包含未经核实的“无需额外费用”承诺。
- 修订回答改为以客户所在地实际可办理方案为准，并明确办理前确认月费、优惠期限和合约期。
- 处理人：当前系统管理员。
- 处理后统计：待处理 39、已复核 1、已修订 1。
- 数据库核对：原回答未改变，修订答案与原回答不同，人工版本为 1，历史记录为 1 条。

这条记录被有意保留，用户可直接进入“对话质检 → 已修订”查看完整验收结果。

## 4. 后端接口

- 质检队列：`GET /admin/api/workspace/{workspace_id}/marketing/quality-review/{current_page}/{page_size}`
- 提交处理：`POST /admin/api/workspace/{workspace_id}/marketing/quality-review/{review_id}/handle`
- 任务复盘：`GET /admin/api/workspace/{workspace_id}/marketing/task/{task_id}/effect/{current_page}/{page_size}`

队列查询参数：

- `task_id`
- `quality_status`：`PASS`、`REVIEW`、`HIGH_RISK`
- `manual_status`：`PENDING`、`CONFIRMED_PASS`、`CONFIRMED_ISSUE`、`REVISED`
- `risk_type`
- `keyword`

处理请求示例：

```json
{
  "action": "REVISE",
  "note": "移除未经核实的免费承诺",
  "revised_answer": "套餐升级是否增加费用，需要以您所在地区实际可办理方案为准。"
}
```

## 5. 权限、隔离和并发处理

- 接口必须登录；未登录返回 401。
- 所有列表和处理操作都按当前工作空间过滤。
- 使用其他工作空间访问质检记录时返回 404，不泄露记录是否存在。
- 处理时在事务内锁定质检主记录，避免两个复核人并发生成相同版本。
- 操作历史使用“质检记录 + 版本号”唯一约束，防止重复版本。

## 7. 大规模逻辑变更的安全边界

本阶段不把人工修订答案自动发给客户，原因是这会改变现有对话主链路。后续若启用发送前拦截，必须满足：

1. 先基于人工处理结果计算每类规则的误报率和真实问题确认率。
2. 只允许确认率足够高的确定性高风险规则进入候选拦截范围。
3. 使用工作空间级开关，默认关闭，可按工作空间灰度。
4. 拦截失败或质检服务异常时不得制造对话接口 500；应按配置降级为转人工或继续旁路记录。
5. 保留模型原回答、拦截原因、最终客户回答及人工处理结果，不能只保存改写后的文本。
