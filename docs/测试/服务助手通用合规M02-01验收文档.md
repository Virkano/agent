# 服务助手通用合规 M02-01 验收记录

日期：2026-09-22。范围：非营销、已关联知识库的简单对话链路。营销对话继续使用已有工作空间级发送前质检策略；无知识库的普通对话和工作流节点暂不由本规则改变。

本步把通用规则接在模型生成与客户发送之间。流式回答先缓冲，完整检查后再发送，避免高风险内容先流出再被拦截；非流式回答使用同一规则。对话记录的 `chat_step.compliance` 只保存规则版本、动作、风险类型、人工复核标记、引用段落 ID 和生成/发送内容 SHA-256，不新增命中词、电话、邮箱或证件号的原文副本。

| 场景 | 结果 |
| --- | --- |
| 有引用、正常回答 | 原样发送，记录引用 ID 与 `PASS` |
| 无引用，未配置指定答案 | 发送可核实资料不足的兜底答复，标记 `NO_REFERENCE` 和待复核 |
| 无引用，应用已配置指定答案 | 保留该答复并记录 `CONFIGURED_FALLBACK`；仍受敏感/隐私规则检查 |
| 包含内部规则、系统提示词、确定性不当承诺等 | 发送统一拦截答复，标记 `SENSITIVE_CONTENT` 和待复核 |
| 包含手机号、邮箱或证件号 | 发送脱敏后的答复，标记 `PRIVATE_DATA` 和待复核 |
| 知识库回答生成异常 | 不向客户发送技术异常详情，使用安全兜底并标记 `RUNTIME_ERROR` |

专项自动化覆盖正常引用、无引用、指定兜底、敏感拦截、隐私脱敏、营销链路不叠加规则，以及流式内容在审核前不发送。目标 Ruff 与 Django 系统检查通过。复验命令：

```bash
set -e
set -a
source .env.local
set +a
./.venv/bin/python apps/manage.py test application.test_answer_compliance --keepdb --noinput
./.venv/bin/python apps/manage.py check
./.venv/bin/ruff check apps/application/answer_compliance.py apps/application/chat_pipeline/step/chat_step/impl/base_chat_step.py apps/application/test_answer_compliance.py
```

此项是粗粒度规则基础，不声称具备语义级事实核验或个人信息全类型识别。`manual_review_status=PENDING` 目前只是记录标记，尚无跨工作空间复核队列和复核操作事实；M02 下一步需补权限隔离的人工复核入口，再用真实产品资料完成“导入 → 索引 → 检索 → 回答 → 引用/拦截记录”验收，之后才可标记 M02 整体完成。
