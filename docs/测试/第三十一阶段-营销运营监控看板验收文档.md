# 第三十一阶段：营销运营监控看板验收文档

## 1. 本阶段目标

把分散在营销任务、客户对话、回答质检、发送前检测、触达批次和转化记录中的数据汇总到一个工作空间级运营页面，使管理员能够先发现问题，再进入原业务页面处理。

本阶段不新增持久化告警、通知渠道或定时采集任务，也不修改现有聊天主流程。

## 2. 页面入口

登录管理端，切换到目标工作空间，打开左侧“运营监控”。

页面路由：`/admin/marketing-operations`

页面支持：

- 按近 7 天、近 30 天、近 90 天查看。
- 按单个营销任务筛选。
- 手动刷新当前数据。
- 从待关注事项跳转到“对话质检”或“营销任务”。

## 3. 指标口径

| 指标 | 口径 |
| --- | --- |
| 客户对话 | 周期内关联当前工作空间营销任务的回答记录数 |
| 对话成功率 | 非运行错误回答数 ÷ 客户对话数 |
| 平均响应时间 | 周期内对话记录 `run_time` 的平均值 |
| 慢响应 | 响应时间超过 10 秒的对话数 |
| 质检通过率 | 自动质检正常数 ÷ 自动质检总数 |
| 待人工复核 | 非正常且人工状态仍为待处理的质检记录数 |
| 灰度拦截 | 发送前处理动作为 `INTERCEPTED` 的记录数 |
| 异常旁路 | 发送前处理动作为 `BYPASSED` 的记录数 |
| 运行错误 | 质检风险类型包含 `RUNTIME_ERROR` 的记录数 |
| 逾期批次 | 截止时间已过且状态不是已关闭的触达批次数 |
| 客户转化率 | 当前状态为已办理的客户数 ÷ 客户总数 |
| Token 消耗 | 周期内问题 Token 与回答 Token 之和 |

所有指标只统计当前工作空间；选择营销任务后，再限制到该任务。

## 4. 健康状态

- `存在高优先级异常`：周期内存在运行错误或发送前检测旁路。
- `有事项需要关注`：没有高优先级异常，但存在逾期批次、待复核记录或慢响应。
- `运行正常`：没有以上异常。

健康状态是只读的实时计算结果，不会反向修改任务、对话或质检记录。

## 5. 待关注事项

第一版自动识别：

1. 对话运行错误。
2. 发送前检测发生超时或异常旁路。
3. 未关闭的触达批次逾期。
4. 问题回答等待人工复核。
5. 对话响应超过 10 秒。
6. 当前没有进行中的营销任务。

点击运行错误、检测旁路或待复核事项，进入“对话质检”；点击逾期批次、慢响应或无运行任务，进入“营销任务”。

## 6. 后端接口

```http
GET /admin/api/workspace/{workspace_id}/marketing/operations-overview?days=7
```

可选参数：

- `days`：只允许 `7`、`30`、`90`，默认 `7`。
- `task_id`：只查看当前工作空间中的指定营销任务；跨工作空间任务返回 404。

接口返回：统计区间、健康状态、核心指标、每日趋势、待关注事项、任务健康明细和生成时间。

## 7. 手工验收步骤

### 正常数据

1. 创建进行中的营销任务和客户。
2. 从客户名单打开智能体对话并完成一次正常回答。
3. 打开“运营监控”。
4. 确认客户对话数增加，运行错误不增加。

### 异常数据

1. 准备一条运行错误回答、一条超过 10 秒的回答或一条发送前旁路记录。
2. 准备一个截止时间已过且未关闭的触达批次。
3. 刷新“运营监控”。
4. 确认健康状态变为“存在高优先级异常”或“有事项需要关注”。
5. 点击待关注事项，确认能够进入对应处理页面。

### 筛选

1. 分别选择近 7 天、近 30 天和近 90 天。
2. 确认统计开始日期和趋势横轴同步变化。
3. 选择单个营销任务，确认指标和任务健康列表只保留该任务数据。

## 10. 本阶段边界与下一步

当前“待关注事项”是每次打开页面时实时计算的结果，还不能认领、备注、关闭，也不会发送钉钉或邮件。

下一阶段开发持久化告警处理闭环：告警规则、去重生成、认领、处理记录、关闭和重新打开；通知渠道在告警闭环稳定后接入。
