# 故障上报模拟 M10-13 验收文档

## 1. 验收范围

对应建设方案 X30“故障上报模拟”。本任务复用 X28 已绑定到预演实例的故障配置快照，建设版本化上报模板、四级故障、分阶段状态机、阶段 SLA、证据引用和不可变上报历史，并纳入实例审计与 X26 统一模拟记录。

粗粒度 V1 边界：附件保存外部引用与元数据，不承担真实对象存储上传；倒计时由已固化的阶段截止时间实时计算，不建设后台定时通知中心。需要通知用户的故障仍复用右上角全局告警铃铛。

## 2. 已交付能力

- 上报模板按工作空间、编号和版本保存，固化默认等级、阶段时长、责任角色与必填字段。
- 只有已应用 X28 故障配置且未进入终态的实例才能创建故障上报，创建时保存完整模板快照。
- 支持一级至四级故障；等级升级只允许向更高严重度转移。
- 状态链为草稿、已上报、处理中、已恢复和已关闭；阶段可独立推进并重置截止时间。
- 支持首次证据和运行中补充证据；引用编号在同一上报内唯一，并保存文件名、类型、大小、说明、添加人和添加时间。
- 列表支持实例、模板、状态、等级、超时与关键字筛选，汇总总数、草稿、活动、恢复、关闭、超时和证据数。
- 每次创建、上报、受理、推进、升级、补证、恢复和关闭都写追加式事件，并同步预演实例事件。
- X26 统一模拟记录新增 `FAULT_REPORT` 类型，提供归一状态、进度、耗时和详情下钻。
- 管理端新增“战情上报塔台”，包含模板轨道、故障等级、阶段管线、实时倒计时、快捷动作、筛选表格、新建与详情抽屉。

## 3. 数据模型与迁移

迁移：`apps/rehearsal/migrations/0012_alter_rehearsalinstanceevent_event_type_and_more.py`。

- `RehearsalFaultReportTemplate`：版本化模板、默认等级、阶段定义和必填字段。
- `RehearsalFaultReport`：实例、模板、可选场景执行、等级、状态、当前阶段、阶段起止、证据、模板快照和摘要。
- `RehearsalFaultReportEvent`：顺序号、动作、前后状态、前后阶段、操作说明和操作人。

## 4. 接口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET / POST | `/admin/api/workspace/{workspace_id}/rehearsal/fault-report-template` | 查询或创建上报模板版本 |
| GET | `/admin/api/workspace/{workspace_id}/rehearsal/fault-report` | 筛选、分页和汇总故障上报 |
| POST | `/admin/api/workspace/{workspace_id}/rehearsal/instance/{instance_id}/fault-report` | 创建故障上报草稿 |
| GET | `/admin/api/workspace/{workspace_id}/rehearsal/fault-report/{report_id}` | 查看模板快照、证据和事件链 |
| POST | `/admin/api/workspace/{workspace_id}/rehearsal/fault-report/{report_id}/operate` | 上报、受理、推进、升级、补证、恢复或关闭 |

## 8. 手工测试方法

1. 打开“故障与场景预演”，确认目标实例已应用 X28 故障配置。
2. 在“故障上报模拟”点击“发起故障上报”，选择实例与模板，填写标题、描述、影响范围，可增加一条证据引用后创建草稿。
3. 依次执行正式上报、受理和推进阶段，观察状态、当前阶段、进度与截止时间变化。
4. 使用“升级故障”选择更高等级；同级或降级应被拒绝。
5. 补充证据后检查详情事实链；恢复后执行关闭，确认终态记录不再计入超时。
6. 使用状态、等级、超时和关键字筛选，核对列表与汇总口径一致。
