# 第三十九阶段：营销告警复盘与问题归因验收文档

## 1. 目标与边界

本阶段在现有告警处理闭环上补齐结构化归因和复盘能力，使已关闭告警能够沉淀为可检索、可统计、可复用的历史经验。

通知入口继续统一收口在后台右上角的全局告警铃铛。本阶段不建设企业微信、钉钉、短信、邮件、Webhook 或独立通知中心。

## 2. 已实现能力

### 2.1 结构化关闭告警

关闭告警时必须填写：

- 处理说明；
- 根因分类：模型、数据、知识库、系统、流程或其他；
- 解决方式：配置调整、数据修复、知识库更新、重试恢复、人工介入、误报或其他。

同时可选填写影响范围。关闭操作会将根因、解决方式及影响范围写入告警当前状态和操作快照，保证处理历史可追溯。

重新打开告警时会清空当前关闭结论，避免旧结论被误认为本轮处理结果；历史关闭操作仍保留在时间线中。

### 2.2 告警复盘看板

营销运营页新增告警复盘区域，支持 7、30、90 天时间窗口以及根因分类筛选，展示：

- 已关闭告警数；
- 已归因告警数；
- 复发次数；
- 平均解决时长；
- 根因分布；
- 解决方式分布；
- 复发告警列表；
- 最近处理经验。

点击复发告警可直接打开对应告警抽屉继续查看。

### 2.3 历史经验复用

告警详情会按相同告警类型查询最多三条历史关闭记录，展示历史根因、解决方式和处理说明，供当前处理人参考。

### 2.4 CSV 导出

复盘结果支持导出 UTF-8 BOM 编码的 CSV，包含告警标题、类型、级别、负责人、根因、解决方式、影响范围、处理说明、触发时间、关闭时间和处理时长。

## 3. 数据库与接口

新增迁移 `0023_marketingalert_impact_scope_and_more`，为营销告警增加：

- `root_cause_category`：根因分类，带索引；
- `resolution_type`：解决方式，带索引；
- `impact_scope`：影响范围。

新增接口：

- `GET /workspace/{workspace_id}/marketing/alert-retrospective`：复盘聚合；
- `GET /workspace/{workspace_id}/marketing/alert-retrospective/export`：复盘 CSV 导出。

现有告警关闭接口扩展结构化归因字段；告警详情和列表返回归因标签及相似历史经验。

## 5. 手工验收步骤

1. 进入营销运营页，打开一条未关闭告警。
2. 只填写处理说明，确认未选择根因和解决方式时无法关闭。
3. 选择根因、解决方式并填写影响范围，关闭告警。
4. 确认告警详情展示结构化归因，时间线保留关闭操作快照。
5. 查看告警复盘区域，确认汇总数字、分布和最近处理经验同步更新。
6. 重新打开该告警，确认本轮当前归因被清空，历史关闭记录仍可查。
7. 再次关闭后确认复发次数增加。
8. 点击导出，确认 CSV 可正常打开且中文无乱码。
9. 在相同类型的新告警中确认可看到相似历史处理经验。
10. 在任意后台业务页确认通知仍仅通过右上角全局告警铃铛展示。

## 6. 后续建议

下一阶段可基于已沉淀的结构化根因继续实现告警降噪：识别短期重复告警、提供合并建议，并按历史经验给出处理建议草稿。该能力仍应复用当前全局铃铛和告警处理台，不新增通知入口。
