# 第五阶段：营销任务效果复盘测试文档

## 1. 本阶段完成内容

本阶段在“营销任务 + 对话归因”的基础上，增加任务效果复盘能力。运营人员可以在营销任务列表中直接查看某个任务带来的会话效果和最近对话内容。

已完成能力：

- 新增营销任务效果接口：
  - `GET /admin/api/workspace/{workspace_id}/marketing/task/{task_id}/effect/{current_page}/{page_size}`
- 营销任务列表新增“复盘”按钮。
- 点击“复盘”后展示任务效果抽屉。
- 复盘抽屉展示：
  - 任务名称
  - 营销场景
  - 会话数
  - 消息数
  - 平均耗时
  - 总 Token
  - 点赞/点踩
  - 疑似跑偏数
  - 运行错误数
  - 最近对话列表
- 最近对话列表展示：
  - 用户问题
  - 回答摘要
  - 运行耗时
  - Token
  - 风险状态
  - 创建时间

## 2. 效果统计口径

当前阶段采用轻量可用口径，不新增统计表，直接基于已有聊天日志聚合：

- 会话数：`application_chat.source.marketing_task_id = task_id` 的会话数量。
- 消息数：上述会话下的 `application_chat_record` 数量。
- 平均耗时：`application_chat_record.run_time` 平均值。
- Token：`message_tokens + answer_tokens`。
- 点赞/点踩：根据 `vote_status` 统计。
- 疑似跑偏：套餐问题中出现明显无关关键词，例如 MySQL、数据库升级、软件升级等。
- 运行错误：回答中出现 `Expecting value` 或 `Traceback`。

## 5. 手工验收步骤

1. 打开后台：

   ```text
   http://localhost:3000/admin/marketing-task
   ```

2. 找到任务：

   ```text
   存量客户套餐升级首轮触达任务
   ```

3. 点击“复盘”。

4. 检查顶部指标：

   - 会话数应大于等于 1。
   - 消息数应大于等于 1。
   - 运行错误数应为 0。
   - 疑似跑偏数应为 0。

5. 检查“最近对话”：

   - 用户问题应能看到套餐升级相关问题。
   - 回答摘要应围绕套餐升级、费用透明、权益确认、转人工条件。
   - 风险状态应显示“正常”。

## 6. 当前边界和后续建议

当前复盘是轻量实时聚合，适合开发联调和小规模验证。后续如果要做生产级营销运营看板，建议继续扩展：

- 客户名单/批次导入。
- 外呼、短信、企微等触达结果回传。
- 意向等级识别。
- 转人工原因分类。
- 按日趋势图。
- 按任务导出对话明细。
- 对回答做合规评分。
- 对疑似跑偏回答支持人工标记和修正。

这些功能建议继续挂在“营销任务”体系下做增量扩展，不建议直接改动现有智能体、知识库和聊天主逻辑。
